# 辞書の直し方

`data/aliases.json` に1行足すだけの作業に見えますが、**入れ方を間違えると
何百本もの配信が別のゲームに吸い込まれます。** 実際に何度も起こしました。
ここは、そのたびに分かったことを規則の形にしたものです。

毎日のコラムの書き方は `data/columns/EDITORIAL.md`。これは辞書のほうの話です。

---

## 0. 落ちているものに気づく方法

辞書の穴は、黙っていても教えてくれません。見る場所は4つ。

1. **`/admin/` の「見落とし候補」。** これがいちばん広く拾います（下に説明）
2. **`/admin/` の未判定リスト。** ゲーム名ごとにまとめて、**配信した人数の
   多い順**に並んでいます。3チャンネル以上のものは色が変わります
3. **`python scripts/check_column.py` の 🔧 の行。** 同じものを文字で出します
4. **コラム執筆の窓からの指摘。** 人が見て気づいたもの。いちばん精度が高い

※ 2026-09-20まで、未判定リストは**題名ごと**に並んでいました。配信者ごとに
題名が違うので「1本」の行が散り、200件の中に埋もれます。それで
『デスゲームの報告書』を19日間見落としました。いまは人数順です。

### なぜ「未判定リスト」だけでは足りないのか（2026-09-25）

たろちんさんから「Pogostuck は集計できているか」と聞かれて調べたら、
5チャンネルが配信していたのに1本も数えられておらず、**しかも毎朝の
アラートにも出ていませんでした。** 理由は2つあります。

1. **未判定リストに入るのは、題名の「先頭」に `【】` があるものだけ。**
   末尾の `【】` は配信者名・事務所名であることが多いので、判定では
   見ないようにしてあります（この判断自体は正しい）。その結果、
   - `…ついに壊れる【Pogostuck/標準】` → 末尾なので記録されない
   - `ポゴ2で一発アウト` → 括弧が無いので記録されない
   が、どこにも残らないまま消えていました。
2. **先頭に `【】` があった2本は拾われたが、片方は `Pogostuck`、
   片方は `ポゴ`。** 別の語として1人ずつに分かれ、「3人以上なら知らせる」
   という条件に届きませんでした。

### 「見落とし候補」の仕組み

判定とは別に、**括弧の位置を問わず**題名の中の「名前らしき部分」を全部見て
数える見張りを置きました（`build_site.py` の `find_misses`）。
判定そのものには触らないので、**ここに何が出てもランキングは動きません。**

- **候補あり（A）** カタログのゲーム名の頭と一致した語。
  `Pogostuck` → 『Pogostuck: Rage With Your Friends』のように**正式名を
  提案できる**ので、1チャンネルでも出します
- **見落とし?（B）** カタログに無い語で、**直近7日に3チャンネル以上**が
  使っているもの。1日だけ見ると2人ずつに散って埋もれるので7日で数えます

過去の見落としで試したところ、Pogostuck（A）・めっちゃカメレオン69人・
デスゲームの報告書29人・トルネコ20人・ゴエモン8人・Feign 7人（すべてB）
が出ました。2026-09-25には、これで16本のゲームが新たに見つかりました。

★★**「候補あり（A）」の提案は、同じゲームとは限らない（2026-11-07）。**
提案は「**カタログのゲーム名の頭が一致した**」だけで出ます。意味は見ていません。

    見落とし候補  #splitbrain  → 提案『Split Brain Samsara』（2026年）
    実際に遊んでいたの        『Split Brain』（Kusa Games・2024年12月5日）

**別のゲームでした。** 題は「視覚と操作が分かれた世界で飲酒協力プレイ」で、
automaton の2024-12-11の記事にある「2人で視界と操作を分担する協力脱出ゲーム」のほう。
`Split Brain Samsara` は名前の頭が同じだけの別作品です。

提案をそのまま信じて別名にしていたら、**3本を間違った行に入れたうえ、
「拾えている」ので見落としリストからも消えて、誰も気づけなくなっていました。**

★**提案が出たら、提案されたゲームのほうを一次ソースで引いて、
題に書いてある内容と合うかを見る。** 頭が一致しただけの提案は、
`Deadly Days` と `Deadly Days: Roadtrip` のように**本当に同じシリーズのこともある**ので、
提案そのものが悪いわけではありません。**確かめる手間を省けない**だけです。

ノイズ（`【女性実況】` のような配信のラベル、事務所名）が出たら
`data/miss_blocklist.json` に足してください。**こちらは判定に使わないので、
間違って足してもランキングは狂いません。** `blocklist.json` のほうは判定にも
使うので、短い英単語を足すと事故ります（`live` を足すと
『Live A Live』が丸ごと消える）。

### 企画名が出たら、ブロックリストは「最後」（2026-09-26）

見落とし候補に `#天下無双ARK` のような企画名が出たとき、
**「企画名だから消す」と機械的に処理してはいけません。** 実際に数えたら、
この企画の配信**36本がどのゲームにも入らずに落ちていました。**

順番はこうです。

1. その企画の配信タイトルを全部見て、**中で遊んでいる実際のゲームを探す**
   （版名を書いている人が何人かは必ずいる）
2. 1つに決まったら、**そのゲームの別名として企画名を登録する。**
   新しいキーは作らない（1章のとおり）
3. どのゲームか決まらないときだけ `miss_blocklist.json`

天下無双ARK は、版名を書いた13本のうち10本（3チャンネル）が
`ARK: Survival Ascended` だったので、ASAの別名にしました。
`【ARK: Survival Evolved】` と冒頭に書いている配信は、判定が冒頭の括弧を
優先するので巻き込まれません。**版を明記した人の表記はそのまま残ります。**

※ 企画タグからゲームを割り出す仕組み（`tag_games()`）は別にありますが、
「同じゲームを指す割合が8割以上」が条件です。この企画は 10/13 = 76.9% で
わずかに届きませんでした。**閾値は下げません**（下げると事故が増える）。
こういう「もう少しで届かない企画」を人の目に届けるのが、見落とし候補の役目です。

### いちばん多い穴のかたち（2026-09-25に数えた）

**「英語名はカタログにあるが、日本語名が無い」。** これが圧倒的です。
IGDB の別名（alternative_names）には、カタコトの日本語名がほとんど
入っていません。実際に確認したところ、

- Chrono Trigger の別名は `CT` だけ。「クロノトリガー」は無い
- Arknights の別名は `明日方舟`（中国語）だけ。「アークナイツ」は無い
- Onimusha: Way of the Sword の別名は `OnimushaWotS.exe` だけ

だから**IGDBから取る項目を増やしても解決しません。**
日本語名は、実際の配信タイトルの中にしか無い。それを拾うのが上の見張りで、
拾った語を一次情報（Steam・4Gamer・ファミ通など）で確かめて
`aliases.json` に足す、という手順が唯一の道です。

英語の見出しで登録したときは、**`data/display_names.json` に日本語の
表示名も必ず足してください。** 足さないとサイトに
`Unseasonable Flowering` と出て、誰にも通じません。

### ★ もう本数が付いている行に表示名を足すときは、URLの台帳も一緒に直す（2026-11-01）

**見落としやすい。** `build_site.py` の `game_slug()` は
**表示名でURLを引く**（`g["n"]` は画面に出す名前）。だから

* 表示名が無い行 → URLは英語名から作られる（`romancing-saga-3`）
* あとから日本語の表示名を足す → **台帳に無い名前になり、新しいURLが切られる**
* 古いURLは誰も指さなくなり、検索に載っていたページが404になる

`data/game_slugs.json` は「一度決めた住所は変えない」ための台帳だが、
**鍵が表示名なので、表示名を変えると鍵ごと別物になって効かない。**
`fix_dict.py` も「表示名が既に別の値です…（URLが変わります）」と
止めてくれるのは**書き換えのときだけ**で、**無いところに足すときは黙る。**

**手順。表示名を足す前に `data/game_slugs.json` を引く。**

    python3 -c "import json;print(json.load(open('data/game_slugs.json')).get('Romancing SaGa 3'))"

住所が出てきたら、**新しい表示名の鍵に同じ住所を書き足す**（古い鍵は消さない）。

```json
 "Romancing SaGa 3": "romancing-saga-3",
 "ロマンシング サ・ガ3": "romancing-saga-3"
```

同じ住所を2つの鍵が指すが、引かれるのは新しいほうだけなので問題ない。
**台帳に住所が無ければ何もしなくてよい**（まだページが作られていない行）。
そのときも、英語の住所のほうが読みやすければ手で書いておける
（`ロマンシング サ・ガ2` → `romancing-saga-2` はそうした）。

#### ★★ 足りなかった ── 日ごとの記録も表示名で保存されている（2026-11-09）

**上の手順は、URLしか直していなかった。** `data/game_days.json`（全期間・全ゲームの
日ごとの本数）も**鍵が表示名**なので、表示名を変えると**その日から別の行として
記録され、過去がちぎれる。**

11-01にこの段を書いたとき、**まさにそれをやっていた。**

    'Romancing SaGa 3'      3日（9/22〜9/26）   ← 表示名を足す前
    'ロマンシング サ・ガ3'    4日（10/27〜11/8）  ← 足したあと

**同じゲームが2つの行に割れたまま2週間動いていた。**
ゲーム別ページの全期間グラフも、月まとめの数も、片方しか見ていなかった。

★**なぜ気づきにくいか。** `fix_dict.py` の見張りは
「**表示名が同じ行が2つ、どちらも本数を持っている**」で鳴る。
これは**鍵が違って表示名も違う**ので鳴らない。10-29のポケモンチャンピオンズと同じ穴。

### 表示名を足すときの手順（3つ。2026-11-09に3つ目を足した）

1. **`data/display_names.json`** に表示名を書く
2. **`data/game_slugs.json`** に、**新しい表示名の鍵で同じ住所**を書き足す（古い鍵は消さない）
3. ★**`data/game_days.json` の古い鍵を、新しい表示名に付け替える**

3つ目の確かめ方と直し方:

```python
import json, collections
g = json.load(open('data/game_days.json', encoding='utf-8'),
              object_pairs_hook=collections.OrderedDict)
old, new = 'Fatal Fury: City of the Wolves', '餓狼伝説 City of the Wolves'
print([d for d in sorted(g) if old in g[d]])        # 何日ぶん残っているか
for day, row in g.items():
    if old in row and new not in row:
        g[day] = collections.OrderedDict(
            (new if k == old else k, v) for k, v in row.items())
import sys; sys.path.insert(0, 'scripts')
from common import write_json; from pathlib import Path
write_json(Path('data/game_days.json'), g)          # ★ write_json を使う
```

★**`json.dump` を素で呼ばないこと。** `write_json` と同じ形（`indent=1`）で
書かないと、**27,000行の差分**になってレビューできなくなる（11-09に一度やった）。
★**`object_pairs_hook=OrderedDict` で読む。** 付け替えで並び順が変わると、
これも差分が無駄に増える。
★**同じ日に新旧どちらの鍵もある日は触らない**（足し合わせると二重に数える）。

### 割れていないかを全部調べる

```python
import json
g = json.load(open('data/game_days.json', encoding='utf-8'))
d = json.load(open('data/display_names.json', encoding='utf-8'))
days = sorted(g)
for k, v in d.items():
    if k == v:
        continue
    a = [x for x in days if k in g[x]]
    b = [x for x in days if v in g[x]]
    if a and b:
        print(f'割れています {k!r}({len(a)}日) / {v!r}({len(b)}日)')
```

**11-09に回したときに出たのは `Romancing SaGa 3` の1件だけ**だった。
表示名を足すたびに回すこと。

### どれを「急ぎ」にするか（2026-10-10 たろちんさんの指摘で直した）

これまで**急ぎ＝「公開中のランキングに違うゲーム名が出ているもの」**だけに
していた。落ちているだけの穴は「急ぎでない」側に回していた。

その分け方だと取りこぼす。10月9日発売の『ドラゴンズドグマ 2:ダークアリズン』が
**13chのうち3chしか拾えていない**のに「急ぎでない」側に入っていた。
たろちんさんの指摘で気づいた。

> 『ドラゴンズドグマ 2：ダークアリズン』が10月9日に発売され、昨日今日で
> 配信が立ち上がっていますが、題の書き方によって半分ほど拾えていません

**違う名前が出ているのと、出るべきものが出ていないのは、同じ重さ。**
このサイトは「次に流行るゲーム」を出す場所なので、**発売直後の作品が
上位30位から丸ごと消えているのは、いちばん見られる形の嘘。**

急ぎにするのは、次のどれか。

1. **公開中のランキングに違うゲーム名が出ている**（従来どおり）
2. **その語のチャンネル数が、その日の30位のチャンネル数以上**
   `site/data.json` の `ranking[-1].channels` と比べれば機械で決まる。
   10/10は30位が9ch。ドグマは13chだったので、この線なら引っかかっていた
3. **発売1週間以内の作品で、3ch以上落ちている**
   発売直後は数字が毎日動くので、30位の線を待っていると間に合わない

2と3は数えるだけで決まる。**朝、宿題に回す前にこの3つを当てる。**

### ⚠️ その線の当て方を間違えた（2026-10-11 たろちんさんの指摘）

線を引いた翌日に、**その線を当て損なった。**

> 宿題の1件目『SURGE City』が大きめです。…直近7日で84本・21チャンネルあるのに、
> 題に「GTA5」「ストグラ」と併記した29本しか拾えていません。残り55本が落ちています。
> なんでこれが「宿題でいい」という判定になってるのかちょっと気になる

**2つ間違えていた。**

#### ① leads.json の数字で判定していた

宿題には `数: 7本 / 4チャンネル（leads.json）` と書いてあった。4chなら30位（7ch）に
届かないので、宿題側に回した。**実際は10月9日だけで15ch。**

`leads.json` は**「先頭の括弧が辞書に無い」題だけ**を拾う仕組み。
だから `【#SURGECity #01 】…【GTA5/…】` のように**ほかの語で当たった題**も、
`🔴人間一日目 #SURGECity DAY1` のように**先頭に括弧が無い題**も、数に入らない。
**落ちている本数を測る道具ではない。**

> **判定には必ず「タイトル全文で数え直した数」を使う。**
> leads.json の数字は、語を見つけるための目印であって、大きさの目安ではない。

実際、同じ宿題の中に「タイトル全文で数え直すと84本/21ch」と**自分で書いてあった。**
書いてあるのに、線を当てる側は leads.json の数のままだった。

#### ② 7日の合計と、1日の30位を比べていた

21chは**7日の合計**で、30位の7chは**その日**の数。窓が違うものを比べていた。

> **比べるのは「その語が1日でいちばん多かった日のチャンネル数」と
> 「その日のランキング30位のチャンネル数」。**

SURGE Cityは10月9日に15ch、その日の30位は7ch。**倍以上。**
正しく当てていれば、初日のうちに急ぎとして出ていた。

#### ③ 「発売」には企画・サーバーの初日も含める

3の線は「発売1週間以内」と書いていたが、SURGE CityはGTAのロールプレイ
**サーバー**で、発売ではない。**企画・サーバー・大会の初日も、発売日と同じに扱う。**
題に「Day1」「1日目」「#01」が並ぶ日は、その日がいちばん人が集まる。

### ⚠️ 穴の大きさを数えるときは `fallback=False`（2026-10-15）

数え直しの手順で `M.extract(t, idx, fallback=True)` を使うと、
**まだ辞書に無いゲームが「入っている」ように見える。**

`fallback=True` は、辞書で引けなかったときに
**冒頭の括弧の中身をそのまま返す**作り（`match.py` の `extract`）。
返り値の2つめが `"unknown"` で、これは**ランキングには入らない**
「確認待ち」の印でしかない。

2026-10-15に『80億分の1』を数えたとき、4本中2本が
`80億分の1` という名前で返ってきた。辞書には1行も無かったのに、
**半分は拾えていると読み違えかけた。**

```
✗ M.extract(t, idx, fallback=True)    # 冒頭の括弧がそのまま返る
○ M.extract(t, idx, fallback=False)   # 辞書で引けたものだけ返る
```

**「いま何本拾えているか」を見るときは必ず `fallback=False`。**
`fallback=True` を使ってよいのは「見落とし候補を集めるとき」だけ。

確かめ方は30秒で済む。こちらのほうが速くて確実:

```
print(idx.exact.get(M.compact('さがす語')))   # None なら辞書に無い
```

※ 毎朝のリマインドのプロンプトに載せている数え直しの雛形は、
  いまも `fallback=True` のまま（本数とチャンネル数しか印刷しないので
  数自体は正しい）。**入り先まで見るときは False に直して使うこと。**

### まとめ ── 朝、宿題に回す前に当てる3つ（2026-10-11 版）

| | 線 | 使う数 |
|---|---|---|
| 1 | 公開中のランキングに違うゲーム名が出ている | ── |
| 2 | **1日でいちばん多かった日のch数 ≧ その日の30位のch数** | **タイトル全文で数え直した数**（leads.json は使わない） |
| 3 | 発売・企画・サーバーの初日から1週間以内で、3ch以上落ちている | 同上 |

## 1. まず「それはゲームか」を疑う

**いちばんやってはいけないのは、ゲームでないものをゲームとして登録すること。**
ランキングに存在しないゲームが生まれ、以後ずっと嘘をつき続けます。

`【】` でくくられた名前は、特に疑ってください。日本の配信の題名では、
`【】` はゲーム名だけでなく、**企画名・チャンネル名・事務所名・視点**にも
使われます。

  ✗ `【おらふくん100万人】金100万個で金盾作るまで終われません！`
    → これはドズル社の登録者100万人記念**企画**の名前。ゲーム名ではない
  ✗ `【#にじ遊戯王祭2026】` → 企画名
  ✗ `【ぶいすぽっ！/橘ひなの】` → 事務所とチャンネル名

企画名だと分かったら、**中で遊んでいる実際のゲームを突き止めて、
そのゲームの別名として登録します。** 新しいキーは作りません。

```json
"Grand Theft Auto V": ["GTA5", "SURGE Town", "サージタウン"],
"Minecraft":          ["マイクラ", "おらふくん100万人"]
```

**実際のゲームが確かめられないときは、登録しません。** 推測で入れない。
題名だけで判断がつかないときは、その配信を開いて「ゲーム」の欄を見る。
それでも分からなければ、そのまま保留にして次の機会を待ちます。

### 企画名を見つけたときの手順（2026-09-21 たろちんさんと決めた）

いまのところ**その都度、人が見て対応**します。自動化はしません。

`【】` の中身から機械的にゲームを引き継ぐ仕組みは作れますが、
`【ドズル社】` のようなチャンネル・事務所の名前も同じ形なので、
**その日たまたま8割がマイクラだっただけで、別のゲームの配信まで
マイクラと判定してしまいます。** 危険のわりに拾えるものが少ない。

頻繁に出るようになったら、あらためて自動化を検討します。

## 2-5. 詰めるとありふれた字になる題名は `alias_exact_only.json` へ（2026-10-23）

2章は「ありふれた語を別名にしない」でした。ここはその**裏側**で、
**題名そのものが、詰めるとありふれた字になってしまう**ときの逃げ道です。

### きっかけ ──『あ。あ。あ。』

マイクに「あ」「ん」と言って操作するゲームが7本落ちていました。
ところが **`compact()` は「。」を落とす**ので、

    compact('あ。あ。あ。')  = 'あああ'
    compact('あ。あ。あ。あ') = 'ああああ'

普通の別名として足すと、

    「しゅばあああああああ」「きたああああ」「だあああ」

のような題を全部さらいます。数えたら **`あああ` を含む題は138本・67チャンネル**
あり、そのうち100本は 7 Days to Die・Apex・ドラゴンボールZカカロットなどに
**正しく入っていました。** 足した瞬間に全部奪います。

**最低文字数を3→4に上げる手は使えません。** 3文字の非ラテン別名は262件あり、
手で登録したものだけでも `ヴァロ` `デドバ` `スト6` `あつ森` `ウマ娘` `学マス`
`パルワ` など24件が効いています。

### 仕組み

`data/alias_exact_only.json` に書いた別名は、
**括弧の中身まるごと（か題名まるごと）がその字と一致したときだけ**当たります。
途中に含まれているだけでは当たりません。

    【あ。あ。あ。】            → 当たる（括弧の中身がまるごと一致）
    「しゅばあああああ」          → 当たらない（途中に含まれているだけ）
    【 あ。あ。あ。 / 配信者名 】  → **当たらない**（括弧に配信者名も入っている）

3つめは取りこぼしますが、そこまで取りに行くと途中一致に戻ってしまうので
**取りません。** 7本中6本が拾えれば十分です。

全期間40,823本で確かめて、**新しく6本 / 失った0本 / 移った0本**でした。

### 使ってよいとき・いけないとき

- ○ **題名が、詰めるとありふれた字になる**（記号で区切った題名、短い擬音の題名）
- ✗ **ただの略称**。それは普通の別名で足す。ここに入れると括弧がまるごとその字
  でないかぎり当たらなくなり、取りこぼしが増える
- ✗ **2章で止めるべき語**。ありふれた語を無理に通す抜け道にしない。
  止めるべきものは `alias_blocklist.json` のほう

※ 2026-10-12に「条件付きで弾く仕掛けは、守るものが無いうちは作らない。
  ただし必要になる日は来る」と書きました。その日が来た、という形です。
  **守るものが出てきてから作る**、は今回も守れています。

## 2-5-5. 「綴りの揺れを全部足す」は、たいてい要らない（2026-11-08）

報告が**綴りの揺れを並べてくる**ことがあります。2026-11-08の `#ガチグラ2` は

    #ガチグラ2 ／ ガチグラ2 ／ ガチグラ２（全角）／
    ガチグラvol.2 ／ #ガチグラvol.2 ／ #ガチグラ

の6つが「全部必要」として挙がっていました。**要りませんでした。**

`compact()` は NFKC して小文字にして `STRIP` の字を落とします。
`#` も `.` も落ちるし、全角の `２` は NFKC で `2` になる。だから

    #ガチグラ2 ／ ガチグラ2 ／ ガチグラ２   → すべて `ガチグラ2`
    ガチグラvol.2 ／ #ガチグラvol.2        → どちらも `ガチグラvol2`
    #ガチグラ                           → `ガチグラ`

**6つが3つにしかならない。** さらに `ガチグラ`（4字）は残り2つの**中に入っている**ので、
**`ガチグラ` を1つ入れれば6通り全部に当たります。**

★**足す前に、候補を全部 `compact()` に通して、何種類になるかを見る。**

```
python3 -c "
import sys; sys.path.insert(0,'scripts')
import match as M
for a in ['#ガチグラ2','ガチグラ２','ガチグラvol.2','#ガチグラ']:
    print(repr(a), '→', repr(M.compact(a)))
"
```

同じ字に詰まる別名を並べても、**辞書が太るだけで1本も増えません。**
長いほうも入れておくのは、**別のゲームと同じ括弧の中で競ったときに勝たせたい**ときだけ
（score は `別名の字数 + 3`）。11-08は `ガチグラ` と `ガチグラ2` の2つにしました。

※ **落ちない字もある。** `『』` は落ちないし、NFKC は `é` を `e` にしません（4-5章）。
  「落ちるはず」と思い込まず、上のとおり実際に通して確かめること。

## 2-6. 裸の別名を足すかは、全期間で数えて決める（2026-10-25）

「`ぷにぷに` を足していいか」「`homeクラ` は危ないか」は、考えて決めるもの
ではなく**数えて決めるもの**です。2026-10-25の1回で5件この判断があり、
同じ数え方で全部片づきました。

```python
import sys, json, pathlib, collections
sys.path.insert(0, 'repo/scripts')
import match as M
idx = M.build_index()
titles = {}
for f in sorted(pathlib.Path('repo/data/daily').glob('*.json')):
    for v in (json.loads(f.read_text(encoding='utf-8')).get('videos') or []):
        titles[v.get('id')] = v.get('title') or ''

word = 'ぷにぷに'                       # 足そうとしている裸の別名
c = M.compact(word)
hit = [t for t in titles.values() if c in M.compact(t)]
cur = collections.Counter()
for t in hit:
    r = M.extract(t, idx)
    cur[r[0] if r else None] += 1
print(len(hit), '本'); print(cur.most_common())
```

出てくる数の読み方。

| 出かた | 意味 |
|---|---|
| ほとんど `None` | **足して得だけが出る。** `homeクラ` は38本中27本が None・11本は既にマイクラ・**損0** |
| 他のゲームに入っている本数がある | **その題を1本ずつ開いて読む。** 正しく入っているなら、足すと奪う |
| 多数が他のゲームに入っている | **足さない。**『あ。あ。あ。』の `あああ` は138本中100本が正しく入っていた（2-5章へ） |

★**損が0でなくても足すことはある。** `ぷにぷに` は28本のうち1本だけ、
とりっぴぃさんのポケモンカード動画（「【ポケカ】…『ぷにぷにサークルデッキ』で…」）が
間違って入る。**得26本・損1本と数えたうえで足した。**
大事なのは数の大小ではなく、**知らずに入れたのか、知って受け入れたのか**です。
受け入れたのなら、直しファイルのメモに**その1本の題まで書き残す。**
あとで「見落とした」と読まれないために。

★**裸の形を足さずに済むなら、そのほうが良い。** 同じ日の
`プロスピ`（→『プロスピ2026』を奪う）、`風来のシレン`（→5plusを奪う）、

（`プロスピA` / `初代 風来のシレン` / `くねくねorくねくね？`）で足りました。

★**重ねても意味は無い。** 報告が `homeクラ` `homeクラ合衆国` `homeクラ3` の
3つを挙げていても、後ろ2つは `homeクラ` を含むので**足す意味がありません。**
別名は短いほうを1つ持てば足ります。

## 2-7. ラテン文字の別名には、決まりが2つある（2026-10-25）

`match.py` のコメントにしか書いていなかったので、**同じ所で2回つまずきました。**
どちらも「仕組みの話だから辞書では直らない」と書いてしまった形です。

### ① 最低4字。3字のラテン別名は「括弧まるごと」のときだけ当たる

`Index.find()` は `len(alias) < (4 if is_latin(alias) else 3)` を飛ばします。
**ラテン文字は4字から、それ以外は3字から**部分一致に乗る、ということです。

    LTK  … 3字。【LTK4】の中では当たらない
    LTK4 … 4字。**当たる**

2026-10-18と10-25に二度「`LTK` が3字なので仕組みの問題。辞書では直らない」と
書きましたが、**`LTK4` を足すだけで直りました**（落ちていた13本/4chが入った）。
直らないのは `LTK` 単体の括弧のほうで、`LTK4` は別の話でした。

**「仕組みの問題」と書く前に、足そうとしている字そのものを数える。**
`P3R` `OW` のような3字以下は `alias_exact_only.json` と同じ振るまい
（括弧まるごとのときだけ当たる）になるので、**その横に一段長い形**
（`ペルソナ3リロード`）を置くと取りこぼしが減ります。

### ★ 手で登録し直すと +3 される（カタログにあるのに負けているとき）

照合の点は `score = len(alias) + (3 if curated else 0)` で、
**手で `aliases.json` に書いた別名だけ +3** される（`curated = pop >= 10**8`）。
だから**カタログに同じ字が入っているのに負ける**ことがある。

2026-10-27の例。YamatoNさんの
『新作シューター COD:MW4 "タルコフモード”『DMZ』をプレーする！』が
『Escape from Tarkov』に入っていた。

    タルコフ   4字 ＋ 手で登録 +3 = 7点
    codmw4     6字 ＋ カタログ由来 +0 = 6点     ← 1点差で負ける

`COD MW4` `MW4` `Call of Duty: MW4` は**カタログにちゃんと入っていた。**
直し方は「足す」ではなく、**同じ字を `aliases.json` に書き直して +3 をもらう**こと。

    CoD:MW4 を手で登録 → 6 + 3 = 9点 → 勝つ

★**同じ字を書き直しても、既に当たっている題の行き先は変わらない**
（上の例では63本のうち62本は既にMW4で、動いたのは1本だけ）。
だから「カタログにあるのに負けている」と分かったら、迷わず書き直してよい。

### ★ 発売したての新作は pop が 0 で、括弧の外では採用されない（2026-10-30）

`Index.find(strict=True)`（＝括弧の外で照合するとき）はこの行を通る。

    if len(alias) < (6 if is_latin(alias) else 4) or pop < 1:
        continue

**カタログの新作は pop（評価数）が 0 のことが多い。** そのため

    戦闘だけで買う価値あるかも。Phantom Blade Zeroは本当に買い？…

のような**括弧がまったく無い題**で落ちる。括弧つきの題では拾えているので、
「だいたい拾えているのに、紹介系のチャンネルだけ落ちる」という見え方になる。

**直し方は上と同じで、手で登録し直す**（pop が 10^9 になって通る）。
既に拾えているぶんの行き先は変わらないので、迷わず足してよい。

### ② 単語の切れ目を求める。くっついた綴りには当たらない

ラテン別名は、**前後が単語の切れ目**でなければ当たりません
（元の文で区切られていた所も切れ目として認めます）。

```
Corridor（8字）を別名に持つ行に対して
  'Shadow Corridor'  → 当たる（空白が切れ目）
  'ShadowCorridor'   → **当たらない**（直前が w で、元の文にも区切りが無い）
```

2026-10-25の日曜の窓が「`ちむらい` さんの【ShadowCorridor】2本が落ちている
理由だけ分からなかった。照合順の問題だと思うが確かめていない」と書いた件は、
**これです。** 照合順ではありません。
`surviv` → ARK Survival、`live` → hololive を拾っていたのを止めた見張りで、
**この2本についてはむしろ守りに働いていました**（落ちてはいたが、
`The Corridor` という違う名前では出ていなかった）。

**つまり、くっついた綴りを拾いたいときは、その綴りを別名として足す。**
見張りを緩めるのではなく、`ShadowCorridor` のような実際の書き方を
1つ別名に入れるほうが安全です。

### ③ ⚠️ カタカナ側の見張りだけ、区切りを見ていない（未修正）

ラテン文字側は `sep[i]`（元の文で区切られていた場所）を切れ目として認めるのに、
**カタカナ側の「単語の途中を切り出さない」見張りは sep を見ていません。**
そのため、**元の題に空白があっても**別名の頭の直前がカタカナだと弾かれます。

    #ゆっくり実況　#プロスピ　#プロスピa     → プロスピA が当たらない（ゆうハルさん6本）

詰めると `プロスピプロスピa` `コルオブデュティモダンウォフェア4` になり、

### ★★ 2026-11-01：その「1行で直る」をやってみて、**取り消した**

5件たまったので直しにいきました。`not sep[i]` を1つ足すだけ。

## 2-8. 2字の名前は、括弧まるごとのときしか当たらない（2026-11-05）

**『雀魂』が全期間445本中176本（4割）落ちていた。**毎日打っている常連ほど

| **割らない字** | **空白**（【Dead by Daylight】が3つに割れる）、**`・`**（『サ・ガ』『ルイス・キャミー』） |

## 2-9. 「題の中の長いほうを採る」組（2026-11-09）

冒頭の括弧は `extract()` で **+150点**もらいます。これはふだん正しいのですが、
**題の中にもっと長い正式名がはっきり書いてあるのに負ける**ことがあります。

    【ロマサガ2】難易度ロマンシング！難関リベンジ守護者戦！
    『ロマンシング サガ2 リベンジオブザセブン』Switch版 実況 Part17

`ロマサガ2`（5字＋3＋50＋**150**＝208点）が
`ロマンシングサガ2リベンジオブザセブン`（19字＋3＋50＝72点）に勝ってしまう。

★**11-01に決めた「裸の `ロマサガ2` は原作」はそのまま正しい。**
これは**裸ではないのに負けている**ときの話で、別の問題です。

### 直し方 ── 点の付け方は触らない

点の付け方を変えると、**いま正しく当たっている何万本に影響します。**
代わりに `data/長いほうを採る.json` に**手で組を書く**形にしました。

```json
"組": { "Romancing SaGa 2": "ロマンシング サガ2 リベンジオブザセブン" }
```

意味は「**`Romancing SaGa 2` が勝ったとき、同じ題に
`ロマンシング サガ2 リベンジオブザセブン` も候補として出ていれば、そちらを採る**」。
**両方が同じ題に出ているときしか効きません。**

全期間40,259本で比べたところ、**変わったのは狙った4本だけ**でした。

### 候補の見つけ方

`scripts/check_series.py` の**2つ目の段**（「題の中に、入り先より長い別のゲーム名が
書いてあるもの」）がそのまま候補になります。あの段は**空振りが少ない**と
書いてあるとおりで、出てきたものを人が読んで決めて、ここに足す。

★**別名を足しても直らないときに、ここを疑う。**
『ロマンシング サガ2 リベンジオブザセブン』は別名（`リベンジオブザセブン` など）が
**前から入っていました。** それでも直らなかったのは、点の付け方の問題だったからです。
**「辞書に無いから落ちている」と「辞書にあるのに負けている」は別の穴。**

## 3. シリーズ名を単体で入れない

シリーズ名は、続編の名前の一部です。だから続編を全部吸い込みます。

  ✗ `"Resident Evil"` → `Resident Evil 6` にも当たり、無印の行に集まる
  ✗ `"龍が如く"` → `龍が如く7` にも当たる
  ✗ `"がんばれゴエモン"` → 13作すべてに当たる

**必ず作品を特定できる形で入れます。**

  ○ `"バイオハザード RE:4"`, `"バイオ7"`
  ○ `"がんばれゴエモン大集合！"`, `"ゆき姫救出絵巻"`

数字の途中で切れる問題も同じです。`FF7` が `FF6` に、`ドラクエVIII` が
`ドラクエV` に当たっていました。`match.py` に数字とローマ数字の
境界を見るしくみを入れて直してありますが、**別名のほうを具体的にするのが
いちばん安全です。**

### ⚠️「長い別名が勝つ」のは、題に長い形が書いてあるときだけ（2026-10-25）

`Index.find()` は**いちばん長い別名**を採る。だから `風来のシレン6` が
辞書に在れば、`風来のシレン` 系を足しても6の配信は取られない ── と考えて、
2026-10-25に `初代シレン` を足した。**1本、移った。**

    【風来のシレン】初代シレンぶりのシレン6 その2【10/21】   （さかなさん）

    辞書に在る別名: 風来のシレン6（7字） / 初代シレン（5字）
    この題に在る字: 初代シレン のみ。**「風来のシレン6」とは書いていない**

書いてあるのは `シレン6` だけで、`風来のシレン6` は無い。
長いほうが勝つのは**両方が題に書いてあるとき**の話で、
長い形が書かれていない題では、短い別名がそのまま通る。

**確かめ方は1つだけ。足す前に、その字を含む題を全期間で引いて、
いまの入り先を数える**（2-6章）。このときは数えていて、`初代シレン` 8本のうち
1本がシレン6に入っていることまで見えていたのに、**勝つ側を読み違えた。**
数えたら、必ず**その1本の題を開いて読む。**

### 数字が付いていても、同じゲームのことがある（2026-09-25 追記）

3章の逆の形。続編だと思って分けると、逆に割ってしまう。

『Pogostuck: Rage With Your Friends』は「ポゴ2」「ポゴ3」と呼ばれる。
続編に見えるが、**Steamの公式ストアページを見ると、マップ2とマップ3は
本編に入っているモード**で、別売りでも別ゲームでもない。
だから `ポゴ1` `ポゴ2` `ポゴ3` は全部同じキーの別名にする。

  ○「ポゴ2」→ Pogostuck: Rage With Your Friends
  ✗「ポゴ2」→ 新しいキーを作る

一方で『Suba Pogo』は、名前が似ていても**別のゲーム**だった
（holo Indieが2026年9月14日にSteamで出した、大空スバルが主役の別作品）。
名前が似ているかどうかではなく、**別の商品として売られているか**で決める。
判断はストアページで確かめる。

### 断れなかった例（2026-09-29）

『リズム天国』とだけ書いた配信が8本・6チャンネルあり、
「日本語名が辞書に無い」として報告が上がった。**入れなかった。**

`リズム天国` はシリーズ名で、GBA・DS・Wii・3DS・Switch に同名の作品がある。
実際、この語を含む配信には次が混ざっていた。

**単体で入れると、その全部を最新作の行に吸い込む。**
いま出ている8本が最新作『ミラクルスターズ』である可能性は高いが、
それは推測なので入れない（1章）。

裏を取ろうとして、その6チャンネルが『ミラクルスターズ』と書いた配信を
別に出していないか全期間で数えたが、**1本も無かった。** 決め手が無い。

こういうものは「直せない穴」として残す。毎朝報告が上がり続けるので、
**朝の定期実行の指示に「判断済み」として1行書いておく。**

単体で持つのは3章に反する、という判断だった。**取り消した。**
たろちんさんの指摘。

    > 「龍が如く」というのがシリーズ最初のゲーム名であり
    > 「龍が如く極」（初代のリメイク）と対応するもの。
    > 「龍が如く1」というゲームはない。
    > シリーズの総称として「龍が如く」という名前を使う人、
    > 例えば龍が如くシリーズの好きなキャラの話をする配信、とかが
    > 「龍が如く」に吸われるのはしょうがないので許容する。
    > ナンバリングやスピンオフ名まで書いているものはそのゲームとして数える。

 ・`龍が如く` / `龍が如く 極` / `龍が如く極` → **龍が如く**（1行）

という形にした。総称として使っている配信（シリーズの好きなキャラの話など）が
この行に混ざるのは**許容する**と決めた。

**こちらは「存在しない `龍が如く1` という別名」まで足していた。**
そんなゲームは無い。シリーズの形だけ見て、作品の実際の名前を
確かめていなかった。

そして**止めると `/g/龍が如く/`（公開中のページ）が404になる**ところだった。
止めないことにしたのでページは残る。
**シリーズ名を止める前に、その名前の行にページがあるかを見ること。**

### ナンバリングの略称は、「いま出ている作品」に寄せる（2026-10-05 たろちんさん）

3章の原則は「シリーズ名を単体で入れない」だが、**番号付きの略称は話が別**。
たろちんさんの判断。

    > 龍が如く極2をやる人は「龍が如く2」と省略して書くパターンが
    > それなりにある気がする。「龍が如く極3」も「龍が如く3」と書く人がいる。
    > 今さら古い「龍が如く2」や「龍が如く3」をやる人はあまりいないと思う。
    > （略）「龍が如く極」シリーズの中にごくまれに古いバージョンをやる配信が
    > 混ざってしまうくらいは誤差でよいかなと思う。

つまり **`龍が如く2` → `龍が如く 極2`**、**`龍が如く3` → `龍が如く 極3`**。
リメイクが出ていて、原作（PS2・PS3）を今から配信する人はほぼいない。
**どちらに寄せても間違いは出るので、数が多いほうに寄せる。**

旧作のほうの行（`Yakuza 2` `Yakuza 3`）からは日本語の別名を**外した。**
2つの行に同じ別名を書くと、どちらが勝つかが dict の順番で決まってしまい、
**辞書を足した順で結果が変わる。** 必ず片方から外す。

ただし **リメイクと外伝は別もの。** 同じ日に注意された。

    > 「龍が如く極3」と「龍が如く3外伝」はどちらも近年出た別ゲーであり、
    > そこを混同しないよう注意が必要

『龍が如く 極３』と『龍が如く３外伝 Dark Ties』は1つの商品として
売られている（2026-02-12）。「別の商品かで決める」（Pogostuck の項）だけで
考えると1行になるが、**中身は別の作品で、配信者も別の名前で書く。**
2行に分けた。`龍が如く3外伝` のほうが長いので、`龍が如く3` より先に当たる。

### ⚠️ 「入っていない」と思い込んで、入っていた行を上書きした（2026-10-05）

**元の別名を消した。** 消えたのは `likeadragoninfinitewealth` と

**次からの手順。**

 1. 探すときは、キーと別名の**両方**を見る。

 2. 行を書くときは `al[k] = [...]`（代入）ではなく、
    **足し合わせる。** 代入は、無いと思っていた行があったときに黙って消す
 3. 渡す前に `diff <(git show origin/main:data/aliases.json) data/aliases.json | grep '^<'`
    を見る。**消えた行が出たら、それが意図した削除か必ず確かめる**

### ⚠️ 行を足すと、その行の名前そのものが「手で登録した別名」になる（2026-10-10）

**これは危なかった。** 『ドラゴンズドグマ 2:ダークアリズン』を直すついでに、
2013年の『ドラゴンズドグマ』にも日本語名を足そうとした。足した瞬間、

```
【ドラゴンズドグマ 2(Dragon's Dogma 2)】本日発売ダークアリズン！…
```

が **`Dragon's Dogma`（2013年）に化けた。** 前後比較に
「移 ドラゴンズドグマ 2 → ドラゴンズドグマ 1本」と出て気づいた。

理由。`aliases.json` に行を足すと、**その行のキー自身も別名として
`pop=10**9` で登録される。** そして `match.py` は手で登録した別名に
長さを+3して優遇する（英日併記の題で日本語が負けないようにした仕組み）。

| 別名 | 行き先 | 長さ | 手で登録 | 点 |
|---|---|---|---|---|
| `dragonsdogma` | Dragon's Dogma | 12 | **はい（←足したせい）** | **15** |
| `dragonsdogma2` | Dragon's Dogma II | 13 | いいえ | 13 |

**短いほうが勝った。** 足す前は `dragonsdogma` がカタログ由来（優遇なし）で
12点だったので、13点の `dragonsdogma2` が勝っていた。

**決まり。足したい行の名前が、別のゲームの名前の先頭と同じなら、足さない。**
`ドラゴンズドグマ` `ファイナルファンタジー` のような、**続編の名前に丸ごと
含まれる名前**がこれに当たる。どうしても足したいときは、続編側も同じ日に
手で登録して、長さで勝てることを前後比較で確かめてから。

今回は2013年のほうを**足さずに引き返した**（1ch2本で、英語名では
すでに拾えていたので、失うものが無かった）。

### ★ 逃げ道のほうを使った例 ── スーパーマリオブラザーズ（2026-11-02）

上の段の最後に「どうしても足したいときは、続編側も同じ日に手で登録して、
長さで勝てることを前後比較で確かめてから」と書いてある。**その逃げ道を
はじめて使った。** 17本が落ちていて、引き返すには大きすぎた。

★★**まず点数を数える。ここで `compact()` が長音を落とすことを忘れない。**

| 別名 | 詰めた形 | 字数 | 手で登録 | 点 |
|---|---|---|---|---|
| `スーパーマリオブラザーズ` | `スパマリオブラザズ` | **9** | はい | **12** |
| `スーパーマリオブラザーズ3` | `スパマリオブラザズ3` | **10** | はい（今日足した） | **13** |
| `マリオ3`（カタログ由来） | `マリオ3` | 4 | いいえ | **4** |

**見た目は12字と13字だが、詰めると9字と10字。**
`ー` が3つ落ちるので、差は1字しかない。**手で登録した側の +3 が無いと逆転する。**
だから「続編側も**手で**登録」なのであって、カタログに行があるだけでは足りない。

`マリオ3` は4点しかないので、**3の配信に `スーパーマリオブラザーズ` が
書いてあるだけで初代に化けていた**（実際、9本がその形だった）。

足したのはこの3つ。**前後比較は 新44本 / 失0本 / 移0本。**

    Super Mario Bros.        ← スーパーマリオブラザーズ     17本
    Super Mario Bros. 3      ← スーパーマリオブラザーズ3     5本（守りのため）
    New Super Mario Bros. U  ← New スーパーマリオブラザーズ U  2本（守りのため）

★**守りは「いま記録に出ている形」までにした。** 同じ一族の
`New Super Mario Bros.`（無印）・`Wii`・`2`・`Super Mario Bros. 35` は
70日ぶんの記録に1本も出ていないので足していない。
**出てきたら、その日に足すこと**（放っておくと初代に化ける）。

★なお `Super Mario Bros. 3` はカタログの日本語名が `マリオ3` で、
サイトに『マリオ3』と出ていた。**愛称であって題名ではない**ので、
表示名を『スーパーマリオブラザーズ3』に直した。
**住所の台帳（`game_slugs.json`）に `マリオ3` は無かった**ので、
0章の「URLごと別物になる」件には当たらない（ページがまだ作られていない）。
**本数のある行の表示名を変えるときは、必ず先に台帳を引くこと。**

## 4-5. 足す前に、その行がもう無いか探す

2026-09-28、『リズム天国 ミラクルスターズ』の日本語名が無いという報告を受けて

### ⚠️ カタログに「ローマ字だけ」の行があることがある（2026-10-17）

4-5章のやり方（日本語の一部で `aliases.json` とカタログを検索する）では、
**この形だけは見つからない。**

2026-10-17、朝の報告は『恐怖夜話 第二夜』を「カタログに1行もありません」と
書いていた。実際には**在った。**

```
Kyoufu Yawa            || alias: ['kyohu.exe']      ← 1作目
Kyoufu Yawa: Dai-ni-ya || alias: ['kyohu2.exe']     ← これ
```

**日本語が1文字も無いので、「恐怖夜話」で検索しても出てこない。**
新しい行を作っていたら、同じゲームが2行に割れていた。

同じ日の『対死靈防衛線』も同じ形で、カタログ名は `Legion Breaker` だった。
こちらは配信の題に "Legion Breaker" を併記した人が1人いたおかげで、
5本中1本だけ拾えていて気づけた。**併記する人がいなければ、
こちらも「カタログに無い」と判断していた。**

#### 見つけ方

**日本語名でSteamを検索して、出てきたページのURL（app番号）ではなく
「その言語での書かれ方」を手がかりにする。**

1. Steamで日本語名を検索する（`store.steampowered.com/search/?term=…&l=japanese`）
2. 同じゲームを**英語ページでも開く**か、英語名・ローマ字名を推測する
   （`恐怖夜話 第二夜` → `Kyoufu Yawa`、`対死靈防衛線` → `Legion Breaker`）
3. その綴りでカタログを引く

```
import sys; sys.path.insert(0, 'repo/scripts')
import match as M
for g in M.catalogue():
    j = (g['name'] + ' ' + ' '.join(g.get('alias') or [])).lower()
    if 'kyoufu' in j or 'yawa' in j:          # ローマ字で探す
        print(g['name'], g.get('alias'))
```

ローマ字・英語でもう一度引く。

**これで13件目**（カピバラ／Drillbound／恐怖夜話／No exceptions＝絶対遵守／

**Annihilated＝勇者パーティはぜんめつしました。（中国語の別名で分かった）**／
**Stack & Sus＝人狼バーガー**）。
**いちばん効いている決まり。**

## 4-6. 足す前に、その語について前に何か決めていないか引く（2026-10-18）

**この文書に書いてあるのは「決まり」で、「過去に下した個別の判断」は
`data/columns/運営メモ.md` にしかありません。** そして運営メモは29万字あるので、
上から読むものではありません。**足そうとしている語で引くものです。**

```python
memo = open('repo/data/columns/運営メモ.md', encoding='utf-8').read()
word = 'ARK'                       # 足そうとしている語・別名
lines, head, seen = memo.split('\n'), '', set()
for i, ln in enumerate(lines):
    if ln.startswith('#'):
        head = ln.lstrip('# ').strip()
    if word.lower() in ln.lower() and head not in seen:
        seen.add(head)                      # 節ごとに1回だけ出す
        print('■', head)
        print('\n'.join(lines[max(0, i - 2):i + 6]))
        print('-' * 60)
print(len(seen), '節で出てきました')
```

`ARK` で21節。素のまま全部出すと36か所になるので、**節ごとに1回だけ**にしている。

失敗です。日曜の定期実行には開発チャットの記憶がなく、この文書の決まりだけでは
そこまで戻れません。運営メモには理由ごと残っています。

実際に見送った／入れなかったものだけでも、これだけあります。

## 5-5. 直すときは scripts/fix_dict.py を使う（2026-10-07）

たろちんさん ──

    > あと毎日辞書の穴を修正するのに大量のトークンを必要としている気がする。
    > 何か効率のいい方法はないだろうか？

毎回やっていたのは同じ手順だった。カタログを引く → 辞書に足す →
全タイトルで前後を比べる → 消えた行が無いか origin と見比べる →
変な文字を探す。**手で10回以上やりとりしていた。** まとめた。

    python3 scripts/fix_dict.py data/直し/2026-10-07.json

直しは JSON 1枚に書く。`別名` `表示名` `機種` `別名をやめる`
`行をやめる` `別名を止める` `見落としから消す語` のどれでも、書いた分だけ当たる。

**速い理由。** 前後比較は、ふだん全タイトルを見る必要がない。辞書に別名を
足して結果が変わりうるのは「その字を含む配信」と「いま触った行に入っている
配信」だけで、**後者もその行のいまの別名の字を含んでいる。** だから
文字列を含むかだけで絞れる。35,000本が1,000〜2,000本になり、
5分が40秒になる。`--full` と答えは変わらない。
**match.py 自体を直した日は `--full`。**

**毎回入っている見張り。**

 ・**同じ別名が2つの行に入っていないか。** これが入っていると、
   どちらが勝つかが辞書の順番で決まる。初回に回したら
   `jsp2` `jsp3` `ff7リバース` `finalfantasyviirebirth` の4件が出た
 ・**表示名が同じ行が2つ、どちらも本数を持っていないか。**
   ランキングに同じ名前が2つ並ぶ。見落としリストには出ないので、
   これが無いと誰も気づけない。『日本事故物件監視協会』で出た
 ・**origin から消えた行・別名。** 直しファイルで宣言した削除は黙る。
   宣言していない削除が出たら、それは事故（2026-10-05にやった）
 ・変な文字（キリル・ハングル・置換文字・ゼロ幅）とJSONの形

**失った配信が1本でもあると、終了コードが1になる。** 意図した削除なら
そのまま進めてよいが、必ず中身を見る。

## 7. 売っている場所も書く

`aliases.json` に手で足したゲームは、IGDBから売り場を引けません。
`data/platforms.json` にも1行足します。

```json
"がんばれゴエモン大集合！": ["pc", "console"],
"がんばれゴエモン ゆき姫救出絵巻": []
```

`["pc","console"]` = SteamとAmazonの両方 / `["console"]` = Amazonだけ /
`["pc"]` = Steamだけ / `[]` = どちらも出さない。

**分からないより、間違ったリンクを出すほうが損が大きい。**
スプラトゥーン3に「Steamで探す」が出ていて、押した人は何も見つけられません
でした。単体で売られていない収録作は `[]` にします。
