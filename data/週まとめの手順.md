定期実行の設定そのものには短い案内しか書いていなくて、中身は全部ここにあります。

■ このまとめの主役は「順位表」ではなく「読みもの」です

順位表の上位は Apex・スト6・マイクラのように毎週同じ顔ぶれになります。固定のファンが
ついているタイトルなので、大きな大会やイベントが無いかぎり読む人の興味を引きません。
**このサイトの価値は、ゲーム配信界隈で何が起きたかを紹介するコラムのほうにあります。**

週まとめは、**その週の注目すべき1つの出来事を選んでコラムとして書く**のが本体。
順位表は後ろに置く記録（おまけ）です。書いたコラムはサイトにも残ります（/matome/）。

毎日のコラムは「その日起きたこと」を書いています。週のコラムは
**1日を見ているだけでは見えないこと**を書いてください。例:
数日かけて広がった／週をまたぐ大会・企画／何度も戻ってくる／時間がたっても落ちない。

■ ★★週まとめの文体は「です・ます」（敬体）にそろえる（2026-11-16 たろちんさん）

> 週まとめコラム、出力された文章が常体と敬体で混ざっているのでいったん敬体に統一してみよう

2026-11-02の週まとめは、本編が「〜が出た。〜である。」（常体）で、「こんなこともありました」と
カードの `sub` が「〜でした。〜ています。」（敬体）だった。**1本の中で2つの調子が混ざっていた。**

**週まとめは、本編・リード・「その週、ほかに」・カードの `sub` と `also`・note の下書きまで、
全部「です・ます」で書く。**

    ✗ 11月5日、『ゼルダの伝説 時のオカリナ』のNintendo Switch 2版が出た。1998年のNINTENDO 64版のフルリメイクである。
    ○ 11月5日、『ゼルダの伝説 時のオカリナ』のNintendo Switch 2版が出ました。1998年のNINTENDO 64版のフルリメイクです。

- **体言止めは使ってよい**（敬体の中に混ぜても不自然にならない。ただし2文続けない）
- **引用の中は元のまま**（配信の題やレビューの言葉は、常体なら常体のまま `「」` に入れる）
- **タイトル（見出し）は文体の外**。これまでどおり言い切りや体言止めでよい
- 「いったん」と言われているので、**試しの決まり**。直されたら、そのとき戻す
- ※ **毎日のコラムと月まとめは常体のまま**（変わったのは週まとめだけ）

4-0. ★★**タイトルの候補を20本出して、たろちんさんに選んでもらう（2026-10-14 版）。**

   **型・字数・禁止事項・B枠の決まりは、全部 EDITORIAL.md の5章にある。必ず読む。**
   とくに「**週まとめ・月まとめも20本。ただし3つだけ決まりが違う**」の節。
   ここには手順だけ書きます。

   ★**20本に入る前に、軸を3つ書き出す。** 1つの観察から20本作らない。
     週まとめの軸はこの3つ（毎日のコラムとは中身が違う）。
       ① 何が起きたか（企画・大会・発売そのもの）
       ② どこが面白かったか（具体的な場面・引用できる一言）
       ③ **1日では見えなかったこと**（数日かけて広がった／週をまたいだ／
          何度も戻ってくる／時間がたっても落ちない）
     **軸ごとに最低2本。**

   **A枠10本（数えた事実だけで作る）** ── ターゲットで割り、ラベルを付けて並べる。
       配信を見る人   4本（引用型・落差型・ネタ型が効く）
       ゲーム好き一般 3本（紹介型・事実の直球。配信は見ていない読者）
       配信する人     3本（圧縮型・事実の直球）
     **このうち3本は軸①**──「何が起きた週だったか」を一言で言う型にする。

   **B枠10本（事実から一歩踏み出す）** ── 型のラベルを付ける。
       仮説型（「？」で止める）／投げかけ型／言い切り型／情景型／逆張り型／再燃型
       ・**推測だと分かる形を6本以上**（？・〜かも・投げかけ）。言い切りは4本まで
       ・**数はざっくり言い換えてよい**（19チャンネル→「続々」）。ただし実際の動きと
         釣り合っていること。2→3chを「急増」は駄目、4〜6→19chなら「続々」でよい
       ・**比喩は誇張してよい。数の主張は誇張してはいけない**（「過去最高」「国内最大」
         「半数以上」は、数えたときだけ）
       ・B枠の言葉は**タイトルだけ。本文には持ち込まない**

   **まとめのタイトルだけの決まり（毎日のコラムと違うところ。ここを間違えやすい）**
   ・**20本すべて、冒頭に『ゲーム名』か企画名を入れる。** まとめは一覧でもカードでも
     Xでも**タイトルだけが単体で出る**ので、固有名詞が無いと何の記事か伝わらない。
     1本でも付け忘れると、それが選ばれたときにそのままXに出る
       ✗ 犯罪の街でいちばん見られたのは黒服の夜
       ○ 『にじ遊戯王祭』犯罪の街でいちばん見られたのは黒服の夜
   ・**全体で35字まで。** 超えるとXの投稿文が280字に入らない。
     冒頭の『ゲーム名』が8〜12字を食うので、本体は15〜25字。
     **毎日のコラムの「3本は30字以上」は、ここには持ち込まない**
   ・**1本ずつ字数を添える**（「（32字）」のように）。35字を超えたものは出さない。
     **字数は『』も「」も句点も含めた全部を数える。目分量で書かない**
   ・**長いゲーム名は通称に縮める**（『トルネコの大冒険 ちょっとステキなリマスター』
     →『トルネコの大冒険』）。縮めるのはタイトルとカードの中だけで、
     `sections` の小見出しはフルネームのままでよい

   **全体の決まり（毎日と同じ）**
   ・**読点を使ってよいのは20本あわせて4本まで。** 節を切るときは句点「。」か
     スペースか「―」。手本46本では「読点だけで節を切った見出し」は9%、
     ハヤリゲーの過去50本では84%だった
       ✗ 『にじ遊戯王祭』犯罪の街で、いちばん見られたのは黒服の夜
       ○ 『にじ遊戯王祭』犯罪の街がひらいた初日。見られたのは黒服の夜
   ・**配信者の名前をタイトルに出さない。** 本文には書く
   ・**釣り・煽り（結論を隠す、断定しすぎ）は書かない**
   ・**`sub` は20本ぶん書かない。** 出すのは `title` の候補だけ。
     たろちんさんが1本選んだあと、その1本に合わせて `sub` を書く
   ・JSONの `title` には**A枠の1本目（いちばん推すもの）**を入れておく。
     別のを選ばれたら、そのとき差し替える

   ※ 企画・大会が主役の週は、冒頭を『ゲーム名』ではなく企画名にしてよい。
     その場合も**配信タイトルに実際に書かれている綴りをそのまま写す。**
     思い出して書かない。年号が1つ違うだけで別物になる。

4-1. ★**カードに載せる3行（"card"）を一緒に書く。**

   週まとめはXにも流します。本文は400〜700字あって、そのままでは1枚の画像に
   入りません。**カードに載せるのは3行だけ**です。**ここも「です・ます」で書く。**

     "card": {
       "sub": "見出しの中身を説明する文。50〜100字",
       "also": ["その他の出来事（20〜44字）", "もう1つ"],
       "pics": [{"u": "https://www.youtube.com/watch?v=…", "by": "チャンネル名"}]
     }

   - **sub … 50〜100字。「何が起きたのか」はここを読めば分かる長さにする。**
     本文の要約ではなく、**本文の頭2〜3文を短くしたもの**を作るつもりで書く
   - **also … 2行。** `sections` の「その週、ほかに」から2つ選んで短くしたもの、
     が基本の作り方。1行44字まで（これを超えると画像のほうで2行に折り返す）
   - **pics … 省いてよい**（2026-10-14 追加）。カードに並べる配信のサムネイル3枚。
     省いたときは `hero` と `sources` の中のYouTubeの動画URLから自動で拾うので、
     ふだんは書かなくてよい。**どの配信を出すか選びたいときだけ**書く。
     `by`（誰の配信か）が無いものは使われない
   - **本編と同じ規律で書く。** 推測を書かない。「当サイトの集計では」の話として書く

   ※ **投稿文に2行とも載るとは限りません。** タイトルが長い週は、入らないぶんを
     スクリプトが後ろから落として、「合わせて何字詰めれば両方載るか」を画面に出します。
     落ちた行も画像には残るので、読めなくなるわけではありません。
     2行とも投稿文に載せたい週は、その字数ぶん `also` を詰めて作り直してください。

   この欄はカードと投稿文だけに使います。**サイトの本文には出ません。**

   ※ 月まとめのカードは形が違います（「今月のハヤリゲー ベスト3」の順位表で、
     `also` ではなく `best` を使う）。週まとめはこの3行の形のままです。

5. **記録（おまけ）。** 短くてよい。週の上位10ゲーム（延べ配信数・のべチャンネル数）、
   前週と比べて伸びたゲーム上位5、何日ぶん集計したか。
   ※ 各日の記録には上位30ゲームしか残っていない。「0本」は「その日30位以内に
     入らなかった」という意味で、1本も無かったとは限らない。そう注記する。

6. **渡すものは4つ。** SendUserFile で（(d)だけは本文に貼る）。
   **報告の並びは「Grokの質問文 → 主役の候補3つと選んだ理由 → 渡すもの」の順。**
   (a) **サイトに載せるJSON。** 先週の月曜の日付で `2026-09-07.json`
       （置き場所は data/columns/weekly/）。形:

         {"title": "冒頭にゲーム名・企画名を入れたキャッチコピー（35字まで）",
          "lead": "リード1〜2文。省略可",
          "sections": [{"body": "本編"},
                       {"h": "その週、ほかに", "body": "短信 2〜4件"}],
          "card": {"sub": "50〜100字", "also": ["…", "…"]},
          "sources": [{"t": "出典の見出し", "u": "https://..."}]}

       声を軸に書いた週は `"声"` の欄も足す（EDITORIAL.md 7-1-2章。サイトには出ない）。
       詳しくは README_まとめ.txt。

       ★**あわせて、タイトルの候補20本を本文に貼る**（ファイルではなく本文。
       選びやすさが大事）。A枠はターゲットの見出しごとに、B枠は型のラベルを付けて、
       通し番号で並べる:

         タイトルはこの20本から選んでください（JSONには①を入れてあります）

         【A枠・事実から】
         配信を見る人
         ① 引用型  『にじ遊戯王祭』「全ロスしました」が並んだ3日間（24字）
                    （ともこうさんの題から）
         ② 落差型  …
         ③ ネタ型  …
         ④ 引用型  …
         ゲーム好き一般
         ⑤ 紹介型  …
         ⑥ 事実の直球（軸①）  …
         ⑦ 紹介型  …
         配信する人
         ⑧ 圧縮型  …
         ⑨ 事実の直球（軸①）  …
         ⑩ 圧縮型（軸①）  …

         【B枠・一歩踏み出す】
         ⑪ 仮説型  …
         ⑫ 投げかけ型  …
         ⑬ 言い切り型  …
         ⑭ 情景型  …
         ⑮ 逆張り型  …
         ⑯ 再燃型  …
         ⑰〜⑳  …

       引用型は**どの配信の題から取ったか**を添える。
       たろちんさんが選んだら、そのときJSONを差し替えて渡し直す。
       **たろちんさんが弾く前提で出してよい。振り切った2〜3本を必ず混ぜる。**
   (b) **ツイート用の画像 … 自分で作らない。手元のcloneでこれを回す:**

         python3 scripts/make_week_card.py data/columns/weekly/YYYY-MM-DD.json --png

       1600×900の画像と投稿文が一時フォルダに出る。画像を SendUserFile で送る。

       ★**この画像には配信のサムネイルが入っていない**（2026-10-14 に変わった）。
       ここからはYouTubeの画像に出られないためで、入れると枠だけが並ぶ。
       **サムネイル入りの投稿用の画像は、JSONをアップして「3. 毎日の更新」を
       回したあと https://hayarige.com/card_w.png に出る。**
       スクリプトがこの案内を画面に出すので、**渡すときにそのまま添えること。**
       （古いものが出たときは、末尾に ?1019 のように日付を足して開き直す）

       画面に字数と注意も出るので、**必ず読んで直してから渡す。**
       280字を超えたときは「あと何文字ぶん超えているか」まで出るので、
       その字数だけ `also` を詰めて作り直す。
       ⚠️「書体が当たっていません」と出た日は、見本と違う書体で出ているので、
       そのことを添えて渡す。
   (c) HTMLプレビュー1枚。上にコラム、下に記録の表。出典はクリックできる <a href>。
   (d) **X投稿文** … (b)と同じ make_week_card.py が書き出し、画面にも出す。
       **その中身をそのまま本文に貼る**（ファイルで送らない。コピーしやすさが大事）。
       形はそろえてあるので、自分で言い回しを変えない:

         先週の #ハヤリゲー（9/14〜9/20）🎮

         ★『にじ遊戯王祭』犯罪の街で、いちばん見られたのは黒服の夜

         こんなこともありました
         ・…
         ・…

         👇詳しくはサイトで
         https://hayarige.com/w/2026-09-14/

       **見出しの頭の ★ はスクリプトが足す。JSONには書かない。**
       **URLの前の「👇詳しくはサイトで」もスクリプトが足す。**
       280字に入りきらないときは sub が自動で落ちる。それは仕様で直さなくてよい。

   ★反映は `data/パソコンから反映する手順.md` のとおり（「OK」をもらってから Push）。
   push すると「3. 毎日の更新」が自動で走り、/matome/ に出る。
   パソコンにつながっていない日だけ、アップ手順を添える: Code タブ → data → columns → weekly →
   「Add file」→「Upload files」→ JSONをドラッグ → 緑の「Commit changes」
   （この push でも「3. 毎日の更新」が自動で走る。Run workflow は要らない）。
   **このとき、サムネイル入りの投稿用の画像（card_w.png）も一緒に作られる。**
   ※ weekly フォルダが無ければ「Add file」→「Create new file」で
     data/columns/weekly/2026-09-07.json と打つと作られる、と案内する。
   ※ 投稿文はこのチャットで渡したものを使うので、アップを待たなくてよい。
     **画像だけは、アップして更新を回したあとの card_w.png を使ってもらう。**

7. 気づいたこと（おかしなゲーム名が上位にある、データが欠けている日がある、など）が
   あれば最後に1〜2行。無ければ書かない。

■ 守ること
- **「初めて」「最初」「今回が初」は、アーカイブ全期間で数えてから書く。数えていないなら使わない。**
- 裏が取れないことを推測で書かない。分からないことは「分からない」と書く。
  **ただしタイトルのB枠と、EDITORIAL.md 5章のC〜Gで認められた書き方は例外**。
- ★**`「」` に入れてよいのは、誰かが実際に使った言葉だけ**（配信の題・Grokの【そのままの言葉】
  のうちURL付きのもの・Steamのレビュー）。自分で作った言い回しは地の文で使う。
- ★**週まとめは「です・ます」。** 本編・その週ほかに・カードの sub と also まで。
- APIキーは受け取らない・扱わない。
- ★**GitHub への反映は `data/パソコンから反映する手順.md` のとおり**（2026-11-18〜）。書き込み先は `data\\columns\\weekly\\`。たろちんさんがこのチャットで「OK」と言ったときだけ Push する。push すると「3. 毎日の更新」が自動で走るので Run workflow は要らない。作業環境の clone からは push しない。パソコンにつながっていない日だけ、下のアップ手順を添える。
- 前置き・挨拶は不要。いきなり本題。
- 開発の相談を始められたら「それは開発用のチャットのほうがいいです。ここでのやりとりは
  翌週には残らないので」と一言添えてから、答えられることには答える。
