週・月のまとめの置き方
======================

毎日のコラムが「その日起きたこと」なのに対して、こちらは
1日を見ているだけでは分からないことを書く読みものです。
2026-09-14に、Xに流して消えるのはもったいないという話になり、
サイトにも残すことにしました。

置き場所
--------
  data/columns/weekly/YYYY-MM-DD.json    その週の月曜の日付
  data/columns/monthly/YYYY-MM.json      その月

  → 出てくるページ
  /w/YYYY-MM-DD/   /m/YYYY-MM/   一覧は /matome/

週と月で、見る軸が違います（2026-09-21 たろちんさんと決めました）
------------------------------------------------------------
  週まとめ … **出来事**を書く。企画・大会・コラボ。週のスケールの現象
  月まとめ … **ゲーム**を書く。何が伸びたか。月のスケールの現象

同じ軸で両方書くと、月まとめが「大きい週まとめ」になって、
読む人が両方読む理由がなくなります。だから軸を分けています。


週まとめの形（sections は2つ）
------------------------------
{
 "title": "30歳の誕生日に、界隈が拠点を焼き合った4日間",
 "lead": "リード。1〜2文。無くてもよい",
 "sections": [
  {"body": "本編。ひとつの出来事を書く。いままでどおり。"},
  {"h": "その週、ほかに",
   "body": "2番手・3番手の話題。2〜4件、1件あたり2〜3文。\n改行で1件ずつ分ける。"}
 ],
 "sources": [{"t": "出典の見出し", "u": "https://..."}]
}

ツイート用のカードに載せる欄（"card"）
----------------------------------------
（2026-09-28 たろちんさんと決めました。2026-10-01に月まとめの形を足しました）

まとめはXにも流します。本文は400〜700字あって、そのままでは1枚の画像に
入りません。**カードに載せるのは、ここに書いたぶんだけです。**

**週と月で、カードの形が違います。**

  週まとめ … 3行サマリー（見出し ＋ 説明 ＋「こんなこともありました」2行）
  月まとめ … 「今月のハヤリゲー ベスト3」の順位表

軸が違うからです（上の章）。週は「出来事」を書くので順位がありません。
月は「今月伸びたゲーム3本」が記事の骨で、見出しも説明もその1位の話に
なっているので、カードも順位表の形にします。


【週まとめの card】

{
 "card": {
  "sub": "見出しの中身を説明する文。50〜100字。カードでは2〜3行になる",
  "also": ["その他の出来事（20〜44字）", "もう1つ"]
 }
}

 ・sub  … 見出しのすぐ下。**「何が起きたのか」はここを読めば分かる**長さにする。
          短いと札が寂しくなり、100字を大きく超えると下の2行を押し出す
 ・also … 「こんなこともありました」として下に並ぶ。**2行。**
          `sections` の「その週、ほかに」から2つ選んで短くしたもの、が基本の作り方。
          1行44字を超えると、**画像のほうで**2行に折り返す

 ※ **投稿文に2行とも載るとは限りません。** 見出しが長い週は、入らないぶんを
   機械が後ろから落として、「合わせて何字詰めれば両方載るか」を画面に出します。
   落ちた行も画像には残っているので、読めなくなるわけではありません。


【月まとめの card】（2026-10-01 たろちんさんと決めました）

> 月まとめのツイート用カードは「今月のハヤリゲーベスト3」にする。
> 1位は大きめに表示、コラムの見出しと要約もそのまま使いつつ、
> 「こんなこともありました」のポジションに2位と3位を配置する。

{
 "card": {
  "sub": "見出しの中身を説明する文。50〜100字。週まとめと同じ",
  "best": [
   {"g": "トルネコの大冒険"},
   {"g": "鬼武者 Way of the Sword",   "n": "9月6日に18人。発売直後"},
   {"g": "モンスターストライク",        "n": "9月26日に15人。周年に合わせて"}
  ]
 }
}

 ・best … 1位〜3位。**`also` は使いません**（2位・3位がその場所に入るので）
   - g … カードに出すゲーム名。**ここは通称でよい。**
          `sections` の小見出しはフルネームのままで構いません。
          長い名前をそのまま入れると、1位は小さく出て、投稿文も280字を超えます
            『トルネコの大冒険 ちょっとステキなリマスター』→『トルネコの大冒険』
            『エースコンバット8 ウイングス・オブ・シーヴ』→『エースコンバット8』
   - n … 2位・3位に添えるひとこと。**30字まで。**「いつ何人」が入ると効きます。
          1位の n は書いても出ません（1位の説明は見出しと sub が受け持つので）
 ・**省いても動きます。** `sections` の小見出し（「1位 ◯◯」）から名前を拾います。
   通称に縮めたいときと、2位・3位にひとことを足したいときだけ書いてください

 ※ **カードの中だけ、見出しの頭の『ゲーム名』が落ちます。**
   まとめのタイトルは冒頭にゲーム名を入れる決まりですが（下の章）、
   ベスト3の札ではその名前を1位としてすぐ上に大きく出します。そのままだと
   同じ名前が2回並ぶためです。投稿文のほうはタイトルを丸ごと使います。
     タイトル 『トルネコの大冒険』新作が下がっていく月に、33年前の…
     カード   1位 トルネコの大冒険
              ★ 新作が下がっていく月に、33年前の…


この欄はカードと投稿文だけに使います。**サイトの本文には出ません。**
省いても動きます（sub が無ければ lead の1文目を使います）。

作り方:

    python3 scripts/make_week_card.py data/columns/weekly/2026-09-14.json --png
    python3 scripts/make_week_card.py data/columns/monthly/2026-09.json --png

**週でも月でも同じこれを使います。** ファイル名で見分けます
（`2026-09-14` なら週、`2026-09` なら月）。札の形も、文字も、投稿文の書き出しも
自動で変わります。画像と投稿文が一時フォルダに出ます。字数と、長すぎる行への注意も画面に出ます。
配信のサムネイルは載せません（載っているのは見出しと、こちらが数えた数字だけ。
借りものが無いぶん、サムネイルが取れない環境でも画像が作れます）。

投稿文は、URLの前に必ずこの1行が入ります（2026-10-01 たろちんさん。週も月も同じ）:

    👇詳しくはサイトで
    https://hayarige.com/m/2026-09/

カードに載るのは3行ぶんで、本文は400〜700字あります。
**URLだけ貼っても「続きがある」ことは伝わらない**ので、文字で誘導します。

カードの書体は、毎日のカードと同じ分け方にそろえてあります（2026-10-01）:
**見出し用の書体（Dela Gothic One）は名前にだけ使う**（サイト名・札・ゲーム名）。
見出しや説明のような「文」は本文用の丸ゴシックです。
以前は週まとめの見出しだけ Dela で、毎日のカードと字が違って見えていました。


まとめのページに出る画像（"hero"）
----------------------------------
（2026-10-01 たろちんさんと決めました）

> 月まとめのページに画像が何もないのは寂しい。

月まとめの出典はSteam・4Gamer・公式サイトで、YouTubeの動画URLがまず入りません。
サイト側は出典からサムネイルを拾う作りだったので、**月まとめには構造として
画像が付きようがありませんでした。** そこでカードを使えるようにしました。

出る画像は、この順に決まります。

  1. JSONに "hero" があれば、そのYouTubeの動画のサムネイル
  2. **ツイート用のカード**（site/w/YYYY-MM-DD/card.png）
  3. 出典に混ざっているYouTubeの動画

    "hero": {"u": "https://www.youtube.com/watch?v=xxxxxxxxxxx",
             "by": "チャンネル名"}

 ・**何も書かなければカードが出ます。** 画像の心配はしなくて構いません
 ・**配信そのものを見せたい回だけ hero を書いてください。**
   週まとめは「出来事」を書くので、その場面のサムネイルが効くことが多い。
   月まとめは1本のゲームの話ではないので、ふつうはカードのままでよい
 ・借りた画像には「画像 YouTube ◯◯」の断りが自動で付きます（by が要る理由）。
   カードはこちらで作ったものなので、断りは付きません

カードの画像は**GitHubのActionsが勝手に作ります。**
「3. 毎日の更新」を回すと、まだ画像の無いまとめのぶんだけ作られて
site/ に入ります。**たろちんさんがアップするのはJSONだけで、画像は要りません。**
（手元で先に作りたいときは `python3 scripts/make_week_card.py --site`）

この画像は、**Xやnoteにそのページのリンクを貼ったときの絵にもなります**
（og:image）。前はどのまとめを貼っても共通の ogp.png で同じ絵でした。


トップに出る期間
----------------
（2026-10-01 たろちんさんと決めました）

> 毎月1日と週まとめが載る月曜日が被る日などもある。
> 月まとめと週まとめは両方トップに出しておくか、一定期間は両方出して
> ある程度経ったらトップから落とす運用にしてはどうだろう

**週から1本、月から1本、合わせて最大2枚**をトップに出します。
前は「期間の終わりが新しいほう1本だけ」だったので、月まとめが出た日に
週まとめがトップから消えていました。

  週まとめ … その週の日曜から **14日**
  月まとめ … その月の末日から **40日**

月のほうが長いのは、1か月に1本しか出ないからです。次の月まとめが出れば、
新しいほうが選ばれて自動的に入れ替わります。
期間から外れたものは、トップから消えても /matome/ の一覧には残ります。


2つ目の節は、本編の後ろに段落としてぶら下げるのではなく、
**小見出しを付けて節として分けます。** 本編は読みものとして
終わり方を作ってあるので、後ろに短信を続けると締まりが消えるためです。

 ・「ほかに」で触れたものにも、**1件ずつ一次ソースが要ります。**
   裏が取れないものは落とす。件数を埋めない
 ・本編で扱った事務所・ジャンルと寄らないように選ぶ
 ・本編との分量比は、だいたい 7:3 まで


月まとめの形（sections は4〜5つ）
--------------------------------
{
 "title": "冒頭にゲーム名を入れたキャッチコピー（「ベスト3」とは書かない）",
 "lead": "リード。1〜2文",
 "sections": [
  {"h": "1位 鬼武者 Way of the Sword", "body": "..."},
  {"h": "2位 ...", "body": "..."},
  {"h": "3位 ...", "body": "..."},
  {"h": "その月、ほかに", "body": "短信 2〜4件"}
 ],
 "card": {"sub": "…", "best": [{"g": "…"}, {"g": "…", "n": "…"}, {"g": "…", "n": "…"}]},
 "sources": [{"t": "...", "u": "https://..."}]
}

タイトルに「ベスト3」と書かない理由。カードの札にその文字が出ますし、
記事は順位表ではなく読みものです。**1位の話を1本の記事として書きます。**
小見出しの「1位 ◯◯」は、カードの best を省いたときの受け皿も兼ねています。

**主役は「今月伸びたゲーム3本」です。総数の多い順ではありません。**
総数で並べると毎月ほぼ同じ顔ぶれになることを、26日ぶんのデータで
確かめました（Minecraft・Apex・ストリートファイター6）。
それは「流行った」の記事ではなく「定番3つ」の記事になります。

各節の中身は、毎日のコラムと同じ A＋B の組み立て（EDITORIAL.md 5章）。
 A どんなゲームか … ジャンル、何をするゲームか、いつ出たか
 B なぜ今月増えたか … 発売した／企画があった／誰かが始めた／更新が来た
**Bが書けないゲームは、数字が大きくても選びません。**

「定番（Apex・マイクラ・スト6など）」の節は**任意**です。
 ・先月とトップ3の顔ぶれが同じなら、触れなくて構いません
   （毎月同じことを書いても読む人に渡るものがない）
 ・**入れ替わったときだけ、それ自体をひとつの節にします。**
   入れ替わりは、それ自体がその月のいちばん大きな出来事かもしれません
 ・どちらなのかは、下の材料スクリプトが判定して出します


タイトルの付け方 ── **冒頭にゲーム名・企画名を入れる**
--------------------------------------------------------
（2026-10-01 たろちんさんと決めました）

  ✗ 新作が下がっていく月に、33年前のダンジョンだけ上がった
  ○ 『トルネコの大冒険』新作が下がっていく月に、33年前のダンジョンだけ上がった

  ✗ 犯罪の街で、いちばん見られたのは黒服の夜
  ○ 『にじ遊戯王祭』犯罪の街で、いちばん見られたのは黒服の夜

**冒頭にゲーム名を足すだけで、何の話か伝わります。** まとめは一覧でも
カードでもXでも、タイトルだけが単体で出ます。そこに固有名詞が無いと、
読む人には何の記事か分かりません。

 ・**長いゲーム名はフルで入れなくてよい。** 通称に縮めます
     『トルネコの大冒険 ちょっとステキなリマスター』→『トルネコの大冒険』
     『エースコンバット8 ウイングス・オブ・シーヴ』→『エースコンバット8』
 ・企画名でも同じ（『にじ遊戯王祭』『SURGE Town』）
 ・**全体で35字くらいまで。** これを超えると、Xの投稿文が280字に入らなくなる
   （下の `make_week_card.py` が、何字削ればよいかまで出します）
 ・説明の一文にはしない。キャッチコピーのまま、頭に名前を足す形がよい

※ **毎日のコラムの見出し（headline）は逆で、ゲーム名を入れません。**
  あちらはサイトでもカードでも、見出しのすぐ上にゲーム名が大きく出るので、
  入れると同じ名前が2回並びます。まとめのタイトルは単体で出るので入れる。
  **出る場所が違うから、決まりも逆になっています。**


共通の書き方
------------
data/columns/EDITORIAL.md と同じです。特に:
 - title は10〜30字のキャッチコピー。説明の一文にしない
 - 「当サイトの集計では」と主語を付ける
 - 「初めて」と書く前に site/d/ の全日付を数える
 - 出典は一次ソースのみ。まとめサイトは使わない

順位について。毎日のランキングの順位は本文に書きません（EDITORIAL.md 2-2章）。
**月まとめの「1位〜3位」はこれと別です。** 毎日の順位は数本の差で入れ替わって
あとから動きますが、月まとめの順位は月をまたいで計算して初めて出てくるもので、
出たあとに動きません。だから小見出しに書いてよいことにしています。

形が違うもの・出典が無いものは、サイトに出ません（更新のログに理由が出ます）。

【月まとめのときだけ】まず材料を出す
────────────────────────────────────────────────────────────
（2026-09-21 たろちんさんと決めました）

月まとめを書きはじめる前に、次の1行を走らせてください。

    python3 scripts/monthly_notes.py 2026-09      ← 対象の月

出てくるもの:
 ・月まとめの材料_2026-09.txt … **サイトの月まとめ用。これを先に読む**
 ・note_2026-09.html          … noteの裏話用（次の章）
 ・標準出力                    … 上の2つの内容

「月まとめの材料」に入っているもの:
 ・今月伸びたゲームの候補10件。先月とくらべた増え方の大きい順
 ・各ゲームのいちばん多かった日と、その日の代表的な配信3本
 ・定番（割合の大きい順）と、**先月とトップ3が入れ替わったかどうか**
 ・初登場かどうかの印

**この材料は「候補」であって「答え」ではありません。**
1〜3位は、上から機械的に3つ取るのではなく、
**「なぜ増えたかを一次ソースで説明できるもの」**を選びます。
理由が書けないものは、数字が大きくても落としてください。

※ 増え方は「人数」ではなく「その日配信していた人のうち何%か」で
  計算しています。このサイトが見ているチャンネルは増え続けていて
  （8/26に343、9/20に1,977）、人数のままだと何もしていないゲームまで
  増えたように見えるためです。実際、人数で並べるとApexが9月の4位に
  来ますが、割合で見ると順位表から消えます。
  ただし**本文に書く数字は「人数」のほうがよい**です。
  「18人が配信した」のほうが読者に伝わります。

【月まとめのときだけ】note用の「裏話レポート」も一緒に渡す
────────────────────────────────────────────────────────────
（2026-09-20 たろちんさんと決めました）

たろちんさんは、この月まとめとは別に、noteの有料マガジンで
「運営の裏側」を書いています。サイトに載せる月まとめは
「裏が取れた事実」だけで書きますが、noteのほうはその逆で、
サイトには書けない話が中身になります。

 ・判定を間違えていた話、それをどう直したか
 ・辞書に何を足したか、なぜ見落としていたか
 ・ランキングや急上昇で目についた動き
 ・PVの推移

これは手で思い出すものではなく、リポジトリの中に全部残っています。
前の章で走らせた `monthly_notes.py` が、同時に note_2026-09.html も
書き出しています（グラフと表の入った1枚のレポート）。

**この HTML を、月まとめの3点セットに足して4つ目として渡してください。**
添えるひとこと: 「noteの裏話用の材料です。ここから書きたいものを選んでください」

中身は材料であって記事ではありません。たろちんさんが自分の感想・分析・
工夫した点を書き加えて記事にします。こちらで記事の形にまとめる必要は
ありません。ただし、気になった点があれば1〜2行だけ添えてよいです
（例:「9月は辞書の穴が3回見つかっています。まとめて1本書けそうです」）。

※ gitの履歴を読むので、浅いクローン（--depth 1）だと履歴が足りません。
  スクリプトが自動で取り直しますが、失敗したら履歴の欄が空になります。
  そのときは「履歴が取れませんでした」とだけ伝えてください。

※ PVのグラフは data/pv.csv があるときだけ出ます。無ければレポートの中に
  貼り方の案内が出るので、そこをたろちんさんに伝えてください。
  形式は1行1日で「2026-10-01,312」。Cloudflareのダッシュボードの
  Web Analytics から日別の数字をコピーして貼るだけです。
