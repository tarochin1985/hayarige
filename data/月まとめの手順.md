定期実行の設定そのものには短い案内しか書いていなくて、中身は全部ここにあります。

■ 今日どのまとめを作るか（今日の日付で決める）

- 毎月 → **先月のまとめ**（必ず作る）
- 1月・4月・7月・10月 → 上に加えて **前の四半期のまとめ**
- 7月 → 上に加えて **上半期（1〜6月）のまとめ**
- 1月 → 上に加えて **前年の年間まとめ**

該当しないものは作らない。最初に「今日は◯◯と◯◯を作ります」と1行書いてから始める。

■ このまとめの主役は「順位表」ではなく「読みもの」です（2026-09-14 たろちんさんと決めた）

順位表の上位は Apex・スト6・マイクラのように毎月ほぼ同じ顔ぶれになります。
固定のファンがついているタイトルなので、大きな大会やイベントが無いかぎり、
並べても読む人の興味を引きません。**このサイトの価値は、ゲーム配信界隈で
何が起きたかを紹介するコラムのほうにあります。**

月・四半期・年のまとめは、**その期間を通して見ないと分からなかったことを3〜5つ選んで
書く「読みもの」**が本体です。順位表は後ろに置く記録（おまけ）です。
**書いた読みものはサイトにも残します**（/matome/ に並びます）。

期間が長いほど「その日の出来事」ではなく**流れ**を書いてください。例えば:

- その期間に現れて、そのまま定着したゲーム（新作の波が根づいたもの）
- 出ては消えを繰り返しているゲーム
- 何かをきっかけに復活した古いゲーム
- 界隈の行事（大会・企画）が周期的に来ていること
- 事務所をまたいで広がったもの／一事務所の中で閉じていたもの

6つの節すべてが常体でそろっていた。**1本の中で混ぜないことだけ守る。**

2-1. ★★**Grokに貼る質問文を、報告のいちばん上に出す（2026-11-16 たろちんさん）。**

   毎朝のコラムと同じく、**月まとめも Xの声とSteamのレビューを材料にする。**

   （追加の料金をかけないための半自動。くわしくは data/朝のリマインドの手順.md の
   「■ Grokに聞いてもらう」）。

   **やること:** 1位〜3位（と、ピックアップに選んだゲーム）が決まったら、
   すぐ下の型を埋めて**報告のいちばん上**に出す。
   **1位のぶんを①、それ以外を②③…と分けて出す**（1つの質問に何本も詰めると、Grokの答えが浅くなる）。
   たろちんさんが1本しか聞けない月は①だけでよい、と添える。
   埋めるのは ［ ］ だけ。**型の文は変えない。**

       次のゲームについて、Xの投稿を調べて教えてください。記事を書くための材料集めです。

       ゲーム: 『［表示名］』（別の書き方: ［略称・その月の題で使われていたタグ］）
       どんなゲームか: ［1文。公式ストアで確かめたことだけ］
       調べる期間: ［先月の1日］〜［先月の末日］の投稿（日本語の投稿を中心に）
       この月に起きたこと: ［1文。発売・大会・アップデートなど、公式で確かめた出来事だけ］

       知りたいのは「この1か月で、どこが、どんな風にウケていたのか」です。
       次の見出しのとおりに、日本語で答えてください。

       【ひとことで】この1か月で何がウケていたのかを1〜2文で。
       【ウケているところ】多い順に3〜5個。それぞれ「どこが」「どんな風に」を具体的に。
         場面・キャラクター・セリフ・仕組みの名前が投稿に出ていれば、それも。
       【月の中の流れ】月の初めと終わりで、話題や反応が変わったところがあれば。
         一度落ち着いてまた話題になった、などの動きも。
       【配信への反応】配信や切り抜きを見た人が、何に反応しているか。
         特定の場面や配信者の名前が挙がっていれば、それも。
       【不満・批判】あれば具体的に。無ければ「見当たらない」と書く。
       【賛否の割合】ざっくりで。例: 好意的8割・否定的1割・その他1割。
       【そのままの言葉】投稿で実際に使われている、印象に残る言い回しを5〜10個。
         必ず原文のまま（言い換えない・つなげない）。それぞれ投稿のURLを付ける。
       【読んだ量】読んだ投稿のだいたいの数。少なかったらそう書く。

       守ってほしいこと:
       ・実際の投稿に書かれていることだけを答える。推測には「推測ですが」と断る。
       ・投稿が少なくて傾向が言えないときは、無理にまとめず「少なくて分からない」と書く。
       ・発売日・売上・アップデートなどの事実は、確かめられなければ「未確認」と付ける。
       ・記事の文章は書かなくてよい。材料だけでよい。

   質問文の下にこの2行を添える:
     「これをXのGrokに貼って、返ってきた答えをこのチャットに貼ってください。声を足して書き直します」
     「貼らなくても、下のまとめはそのまま使えます。1本だけ聞くなら①を」

   **埋めるときの注意**
   - **YouTubeから取ったもの（配信の題・チャンネル名・本数）は質問文に書かない。**
     渡すのはゲーム名・どんなゲームか・期間・公式で確かめた出来事まで。
   - 常連のゲーム（マイクラ・Apexなど）は、**その月の大会名・アップデート名を必ず入れる。**
     入れないと、そのゲームの一般的な評判が返ってきて、その月の話にならない。
   - 四半期・年間のまとめでは、期間をその長さにして同じ型で出す（【月の中の流れ】は
     「期間の中の流れ」に読み替える）。

   **答えが貼られたら:** EDITORIAL.md 5章G のとおり、その節を声を軸に書き直す。
   声と傾向は使ってよい。**事実（日付・数字・アップデートの中身）は一次ソースで確かめたものだけ。**
   `「」` で使ってよいのは【そのままの言葉】のうちURLが付いているものだけ。
   JSONに `声` 欄を足す（EDITORIAL.md 7-1-2章。サイトには出ない）。

3-1. ★**カードに載せる欄（"card"）を一緒に書く。**

   まとめはXにも流します。本文は長いので、そのままでは1枚の画像に入りません。
   **月まとめのカードは「今月のハヤリゲー ベスト3」という順位表の形**です
   （2026-10-01 たろちんさんと決めた。週まとめとは形が違います）。

     1位 … ゲーム名を大きく ＋ タイトル（見出し） ＋ 説明（sub）
     2位 3位 … その下に横並び。名前とひとこと
     いちばん下 … 配信のサムネイル3枚（2026-10-14 に追加）

     "card": {
       "sub": "タイトルの中身を説明する文。50〜100字",
       "best": [
         {"g": "トルネコの大冒険"},
         {"g": "鬼武者 Way of the Sword", "n": "9月6日に18人。発売直後"},
         {"g": "モンスターストライク", "n": "9月26日に15人。周年に合わせて"}
       ]
     }

   - **sub … 50〜100字。「何が起きたのか」はここを読めば分かる長さにする。**
     1つめの節（1位の節）の頭2〜3文を短くしたもの、を作るつもりで書く
   - **best … 1位〜3位。`also` は使いません**（2位・3位がその場所に入るので）
     - g … カードに出すゲーム名。**ここは通称でよい。**
       `sections` の小見出しはフルネームのままで構いません。長い名前をそのまま
       入れると、1位は小さく出て、投稿文も280字を超えます
         『トルネコの大冒険 ちょっとステキなリマスター』→『トルネコの大冒険』
         『エースコンバット8 ウイングス・オブ・シーヴ』→『エースコンバット8』
     - n … 2位・3位に添えるひとこと。**30字まで。**「いつ何人」が入ると効きます。
       1位の n は書いても出ません（1位の説明は見出しと sub が受け持つので）
   - **サムネイルは自動で入るので、ふだんは何も書かなくてよい**（2026-10-14 追加）。
     1位〜3位のゲームそれぞれについて、その月いちばん見られた配信のサムネイルを
     記録ページから1枚ずつ拾います。**月まとめの出典はプレスリリースばかりで
     YouTubeの動画URLがほとんど無い**ので、この仕掛けを足しました。
     どの配信を出すか自分で選びたいときだけ、`card` にこれを足す:
         "pics": [{"u": "https://www.youtube.com/watch?v=…", "by": "チャンネル名"}]
     `by`（誰の配信か）が無いものは使われません
   - **省いても動きます。** `sections` の小見出し（「1位 ◯◯」）から名前を拾います。
     `best` を書くのは通称に縮めたいときと、2位・3位にひとことを足したいときだけ
   - **本編と同じ規律で書く。** 推測を書かない。数字は実ファイルから計算したもの

   この欄はカードと投稿文だけに使います。**サイトの本文には出ません。**

4. **記録（おまけ）をまとめる。** 読みものの後ろに置く。
   - 期間の上位10ゲーム（延べ配信数・のべチャンネル数）
   - 月ごとの上位3（四半期以上のまとめのとき。移り変わりが見えるように）
   - 何日ぶん集計したか

5. **渡すものは5つ。** SendUserFile で送る（(e)だけは本文に貼る）。
   **報告の並びは「Grokの質問文 → 今日作るもの → 渡すもの」の順。**
   (a) **サイトに載せるJSON。** ファイル名は対象の月で `2026-09.json` のように作る
       （置き場所は data/columns/monthly/）。形:

         {"title": "冒頭にゲーム名・企画名を入れたキャッチコピー（35字まで）",
          "lead": "リード1〜2文。省略してよい",
          "sections": [{"h": "1位 ◯◯", "body": "本文。改行で段落が分かれる"},
                       {"h": "2位 ◯◯", "body": "本文"},
                       {"h": "3位 ◯◯", "body": "本文"},
                       {"h": "その月、ほかに", "body": "短信 2〜4件"}],
          "card": {"sub": "50〜100字",
                   "best": [{"g": "1位の通称"},
                            {"g": "2位の通称", "n": "ひとこと30字まで"},
                            {"g": "3位の通称", "n": "ひとこと30字まで"}]},
          "sources": [{"t": "出典の見出し", "u": "https://..."}]}

       声を軸に書いた月は `"声"` の欄も足す（EDITORIAL.md 7-1-2章。サイトには出ない）。
       四半期・上半期・年間のまとめも同じ形で、ファイル名は期間の最初の月にする
       （例: 2026年下半期 → 2026-07.json は月まとめと衝突するので、
        その場合はたろちんさんに「どの名前で置くか」を尋ねる）。
       詳しくは README_まとめ.txt。

       ★**あわせて、タイトルの候補20本を本文に貼る**（ファイルではなく本文。
       選びやすさが大事）。A枠はターゲットの見出しごとに、B枠は型のラベルを付けて、
       通し番号で並べる:

         タイトルはこの20本から選んでください（JSONには①を入れてあります）

         【A枠・事実から】
         配信を見る人
         ① 引用型  『トルネコの大冒険』「33年ぶりの地下」が並んだ月（25字）
                    （◯◯さんの題から）
         ② 落差型  …
         ③ ネタ型  …
         ④ 引用型  …
         ゲーム好き一般
         ⑤ 紹介型  …
         ⑥ 事実の直球（軸①）  …
         ⑦ 紹介型  …
         配信する人
         ⑧ 圧縮型  …
         ⑨ 事実の直球（軸①）  …
         ⑩ 圧縮型（軸①）  …

         【B枠・一歩踏み出す】
         ⑪ 仮説型  …
         ⑫ 投げかけ型  …
         ⑬ 言い切り型  …
         ⑭ 情景型  …
         ⑮ 逆張り型  …
         ⑯ 再燃型  …
         ⑰〜⑳  …

       引用型は**どの配信の題から取ったか**を添える。
       たろちんさんが選んだら、そのときJSONを差し替えて渡し直す。
       **たろちんさんが弾く前提で出してよい。振り切った2〜3本を必ず混ぜる。**
   (b) **ツイート用の画像 … 自分で作らない。手元のcloneでこれを回す:**

         python3 scripts/make_week_card.py data/columns/monthly/2026-09.json --png

       **名前は week だが、月まとめもこれで作る**（ファイル名で見分けている）。
       1600×900の画像と投稿文が一時フォルダに出る。画像を SendUserFile で送る。

       ★**この画像には配信のサムネイルが入っていない**（2026-10-14 に変わった）。
       ここからはYouTubeの画像に出られないためで、入れると枠だけが並ぶ。
       **サムネイル入りの投稿用の画像は、JSONをアップして「3. 毎日の更新」を
       回したあと https://hayarige.com/card_m.png に出る。**
       スクリプトがこの案内を画面に出すので、**渡すときにそのまま添えること。**
       （古いものが出たときは、末尾に ?1101 のように日付を足して開き直す）

       画面に字数と注意も出るので、**必ず読んで直してから渡す。**
       ・「1位の名前が長いので小さく出ます」と出たら、`card.best` に通称を書いて作り直す
       ・280字を超えたときは「あと何文字ぶん超えているか」まで出る。
         1位〜3位の名前を通称に縮めるか、タイトルを短くして作り直す
       ⚠️「書体が当たっていません」と出た日は、見本と違う書体で出ているので、
       そのことを添えて渡す。
   (c) HTMLプレビュー1枚。上に読みもの、下に記録の表。
       出典は必ずクリックできる <a href> にする。
   (d) note などに貼れる記事の下書き（見出し＋本文のテキスト）。事実だけ。
       ※ **noteはサイトの流入元の2番目です**（2026-10-01の計測でXとほぼ同じ規模）。
         ここは手を抜かずに書くこと。
   (e) **X投稿文** … (b)と同じ make_week_card.py が書き出し、画面にも出す。
       **その中身をそのまま本文に貼る**（ファイルで送らない。コピーしやすさが大事）。
       形はそろえてあるので、自分で言い回しを変えない:

         9月の #ハヤリゲー ベスト3🎮

         ★『トルネコの大冒険』新作が下がる月。33年前のダンジョンだけ上がった

         1位 トルネコの大冒険
         2位 鬼武者 Way of the Sword
         3位 モンスターストライク

         👇詳しくはサイトで
         https://hayarige.com/m/2026-09/

       **見出しの頭の ★ はスクリプトが足す。JSONには書かない。**
       **URLの前の「👇詳しくはサイトで」もスクリプトが足す。**
       280字に入りきらないときは sub が自動で落ちる。それは仕様で直さなくてよい。

   ★反映は `data/パソコンから反映する手順.md` のとおり（「OK」をもらってから Push）。
   push すると「3. 毎日の更新」が自動で走り、/matome/ に出る。
   パソコンにつながっていない日だけ、アップ手順を短く添える:
     Code タブ → data → columns → monthly →「Add file」→「Upload files」→
     JSONをドラッグ → 緑の「Commit changes」
     （この push でも「3. 毎日の更新」が自動で走る。Run workflow は要らない）。
     **このとき、サムネイル入りの投稿用の画像（card_m.png）も一緒に作られる。**
   ※ monthly フォルダがまだ無い場合は「Add file」→「Create new file」で
     ファイル名欄に data/columns/monthly/2026-09.json と打つと作られる、と案内する。
   ※ 投稿文はこのチャットで渡したものを使うので、アップを待たなくてよい。
     **画像だけは、アップして更新を回したあとの card_m.png を使ってもらう。**

6. 気づいたこと（データが欠けている、おかしなゲーム名が上位にある、など）が
   あれば最後に1〜2行だけ添える。無ければ書かない。

■ 守ること
- **「初めて」「最初」「今回が初」と書くときは、必ず全期間で数えてから書く。
  数えていないなら、その言葉を使わない。** 記録ページは上位30件しか無いので、
  data/game_days.json のほうで数えること。
- 裏が取れないことを推測で書かない。分からないことは「分からない」と書く。
  **ただしタイトルのB枠と、EDITORIAL.md 5章のC〜Gで認められた書き方は例外**。
- ★**`「」` に入れてよいのは、誰かが実際に使った言葉だけ**（配信の題・Grokの【そのままの言葉】
  のうちURL付きのもの・Steamのレビュー）。自分で作った言い回しは地の文で使う。
- APIキーは受け取らない・扱わない。
- ★**GitHub への反映は `data/パソコンから反映する手順.md` のとおり**（2026-11-18〜）。書き込み先は `data\\columns\\monthly\\`。たろちんさんがこのチャットで「OK」と言ったときだけ Push する。push すると「3. 毎日の更新」が自動で走るので Run workflow は要らない。作業環境の clone からは push しない。パソコンにつながっていない日だけ、下のアップ手順を添える。
- 前置き・挨拶は不要。いきなり本題。
- 開発の相談（コードを直したい等）を始められたら「それは開発用のチャットのほうがいいです。
  ここでのやりとりは翌月には残らないので」と一言添えてから、答えられることには答える。
