# ハヤリゲー — はじめかた

このフォルダの中身をGitHubに置いて、ボタンを3回押すだけです。
コマンド入力はありません。

---

## 手順1　GitHubに置き場所を作る

1. GitHubにログイン → 右上の **+** → **New repository**
2. Repository name に `hayarige`
3. **Private** を選ぶ
4. 「Add a README file」に **チェックを入れない**（このフォルダに入っています）
5. **Create repository**

## 手順2　ファイルを全部アップロードする

1. できたリポジトリの画面で **Add file** → **Upload files**
2. このZIPを展開したフォルダの**中身をまとめて**枠の中にドラッグ＆ドロップ
   （`scripts` `data` `site` `.github` の4フォルダと `README.md`）
3. 一番下の **Commit changes** を押す

> `.github` フォルダが見えない場合は、パソコンの設定で「隠しファイルを表示」にしてください。
> Windowsはエクスプローラーの「表示」→「隠しファイル」、Macは `Command + Shift + .` です。

## 手順3　3つのキーを金庫に入れる

1. リポジトリの **Settings** タブ
2. 左メニュー **Secrets and variables** → **Actions**
3. **New repository secret** を押して、**3回**登録します

| Name（名前） | Secret（中身） |
|---|---|
| `YOUTUBE_API_KEY` | YouTubeのAPIキー |
| `TWITCH_CLIENT_ID` | Twitch の Client ID |
| `TWITCH_CLIENT_SECRET` | Twitch の Client Secret |

**名前は大文字・アンダースコアまで完全に一致させてください。**
ここが1文字違うだけで動きません。うまくいかないとき最初に疑う場所です。

## 手順4　ボタンを3回押す

**Actions** タブを開きます。初回は「I understand my workflows...」という緑のボタンが出るので押してください。

左側に3つのメニューが並びます。**上から順に**実行します。

### ① 1. まず動作確認（セルフテスト）

左で選ぶ → 右の **Run workflow** → もう一度 **Run workflow**

1分ほどで終わります。緑のチェックが付けば成功です。
クリックして中を開くと、こんな表示が出ます。

```
【1/3】YouTube APIキーを確認します …
  ✅ 成功　テスト取得: hololive ...
【2/3】Twitchのキー（ゲーム辞書用）を確認します …
  ✅ 成功　テスト取得: ELDEN RING
【3/3】同梱データを確認します …
  ✅ チャンネル候補 372 件を読み込めました
```

**赤い×が出たら、そこに書かれているメッセージをそのまま私に送ってください。**
原因がすぐ分かります。自分で直そうとしなくて大丈夫です。

### ② 2. チャンネル情報を集める

同じように実行します。「ゲーム辞書も作り直す」は **yes** のままで。

**15〜30分かかります。** 待っている間は閉じて構いません。
やっていることは3つです。

- IGDBから約5万本のゲーム名辞書を作る
- 名前しか分かっていない48チャンネルのIDを自動で調べる
- 全チャンネルの登録者数・最終投稿日・ゲーム動画率を取得する

終わったら、画面の下のほうにある **channels_review** をダウンロードしてください。
CSVファイルが入っています。これが選別用の表です。

### ③ 3. 毎日の更新

一度手動で実行して、緑になることを確認します。
そのあとは**毎朝7時ごろに自動で動きます**（GitHubの混み具合で数十分ずれます。故障ではありません）。

---

## そのあと

### チャンネルの選別

`channels_review.csv` をExcelかGoogleスプレッドシートで開きます。
**自動判定** の列にすでに判定が入っています。

- `残す` … ゲーム動画率40%以上・登録者1000人以上・活動中
- `外す（1年以上更新なし）`
- `外す（ゲーム動画がほぼ無い）`
- `要確認` … ここだけ見てください

**「要確認」の行だけ**、チャンネルURLを開いて2〜3秒で判断します。
判断がついたら「あなたの判定」列に `残す` か `外す` と書いて、私に送ってください。反映します。

### サイトの公開

Cloudflare Pagesにつなぐと、`site` フォルダがそのままサイトになります。
手順は別途お渡しします。

## 困ったときの見かた

| 症状 | 見るところ |
|---|---|
| 赤い×が出た | Actionsタブ → 失敗した行をクリック → 赤い文字をコピーして私に送る |
| サイトの日付が2日以上古い | 自動更新が止まっています。同上 |
| `quotaExceeded` と出た | その日の無料枠を使い切りました。翌朝には自動で復活します |
| データが空っぽ | ②を先に実行したか確認してください |

**エラーメッセージは、そのままコピーして送ってもらうのが一番早いです。**
要約したり、直そうとしたりしなくて大丈夫です。

## 中身の説明（読まなくても動きます）

```
scripts/
  selftest.py         キーが正しいか確認する
  igdb_sync.py        IGDBからゲーム名辞書を作る（月1回）
  enrich_channels.py  チャンネル情報を集める（月1回）
  fetch_daily.py      新着の配信を集める（毎日）
  build_site.py       集計してサイトを作る（毎日）
  match.py            配信タイトルからゲーム名を判定する（心臓部）
  common.py           API呼び出しとクォータ管理

data/
  channels.tsv           チャンネル候補 372件
  aliases.json           「スト6」などの略称一覧
  blocklist.json         「歌枠」などゲーム名でない語
  channels_manual.json   あなたの手動判定（最初は空）
  daily/                 日ごとの収集データ

site/
  template.html   サイトの見た目
  index.html      毎日自動で作り直されます
```

### クォータ（YouTubeの1日の利用枠）について

1日10,000ユニットまで無料です。今の設計での使用量は、

| 処理 | 消費 |
|---|---|
| 毎日の更新 | 約3,000〜4,000 |
| チャンネル情報の取得（月1回） | 約1,000〜6,000 |

**上限9,000に達すると自動で止まります。** 使い切って翌日動かなくなることはありません。
